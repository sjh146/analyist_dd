# analyist_dd 역할 게이트 (감사·안전·릴리스)

analyist_dd 의 가상 역할 체계에서 **게이트를 돌리고 확장하는 절차**. 설계 정본은 레포
`docs/QUANT_ROLE_PLAN_V2.md` 이고, 실행 명령·판정 표는 `references/role-gate-toolkit.md` 에 있다.
역할 틱 자체의 상태 보고는 `trading-stack-status-report`, 모델 학습·승격은 `quant-model-engineer` 소관이다.

## 역할 집합은 '소유자 없는 일'에서 역산한다 (순서가 반대다)

외부 카탈로그(gstack 등)의 역할명을 우리 시스템에 이식하지 마라. 순서는:
**① 이 스택에서 소유자 없는 일을 실측으로 뽑고 ② 트리거(시간/이벤트)와 산출물 파일이 붙는 것만 역할로 채택**한다.
채택 조건 3개를 모두 만족해야 한다 — (a) 소유자 없는 일이 실측으로 확인됐다 (b) 트리거가 특정된다("항상 조심"은
역할이 아니다) (c) 산출물이 파일이다(산문은 게이트가 아니다). 외부 역할명을 그대로 옮기면 우리에게 **없는 일**
(웹앱 QA·PR 배포·디자인 리뷰)을 담당하는 빈 역할이 생긴다 — 첫 설계 5개 중 3개가 그렇게 무효였다.

현행 5역할:
- `quant-council` 전략회의 — 금 16:00 **대화형(대표 참여)**. 자원·문턱·우선순위 판단. 결정마다 **되돌리는 조건**
  필수, 문턱·한도 변경은 실행하지 않고 **승인 요청**으로만 올린다. 산출 `docs/council/<날짜>.md`.
- `quant-protocol-lock` 계획 락 + 큐 심사 — 이벤트(백로그 승격·릴리스 요청) + 평일 15:55. 락(목표·대조군·성공 문턱·
  est_minutes·timeout·표본 출처·**데이터 소스별 러너·스케줄 표**·롤백) 없는 착수는 **거부**. 핸드오프 미소비를
  소비 계획과 함께 배정한다.
- `quant-auditor` 두 모드 — 평일 15:50 + 실험·릴리스 종료 직후. 모드A 경로(루프 기동 vs 청산창·브리지 반쪽세션·
  피드 신선도·컨테이너 재생성창 침범), 모드B 측정(창 OOS/인샘플 표시·pooled−날짜별 gap·`per_exp` 오용·유니버스
  재현성·**라이브 스코어 분포**). 릴리스 대상 실패는 **보류 통보권**.
- `quant-safety` 실주문 안전 — 평일 08:25 · 14:45(**창 전**). 킬스위치·한도 일치·페이퍼 검증·**창 전 세션 생존**·
  fees. 경보와 **사람 단계 요청**까지만; 킬스위치 발동·한도 변경은 대표 승인.
- `quant-release` 릴리스 — 이벤트 트리거. 동결→백업→dry-run→적용→**15분 검증**→롤백. 승인 항목(챔피언 최종 승격·
  크론·계약)은 실행하지 않는다.

## 불변 규칙

1. **신규 감사·릴리스 역할은 생산 파일을 소유하지 않는다.** 읽기 전용 + 자기 산출 디렉터리
   (`reports/{audit,safety,locks,releases}`, `docs/{council,releases,locks}`)만 write 한다. 소유를 겹치면 형제
   동시 편집으로 한쪽 작업이 소실되는 사고가 재발한다.
2. **시각 창에 묶인 검사는 감사관과 분리한다.** 창(09:00–09:10 익일 시가 청산, 14:50–15:29 close 진입) 전에 돌아
   사람에게 요청을 올려야 하는 검사(세션 생존)를 일일 감사에 섞으면 **창을 놓친 뒤에 보고**하게 된다.
3. **게이트는 실행 가능한 검사로 만든다.** 통과를 주장할 수 있는 산문은 게이트가 아니다. 검사 결과는 JSON 파일로
   남기고 종료코드로 판정한다(0 정상 / 2 이상 / 3 사람 단계).
4. **차단과 경고를 처음부터 갈라 둔다.** 사람 승인 대기·다음 파이프라인에서 갱신될 항목을 차단으로 두면
   릴리스가 영구히 막히고, 반대로 창 전 세션 생존·문턱 불일치를 경고로 내리면 사고가 그대로 통과한다.
   분류표는 `references/role-gate-toolkit.md`.
5. **"무엇을 할까"를 물을 때 이미 돌고 있는 틱을 다시 시키지 않는다** — 그 역할의 산출물(원장·감사 JSON·릴리스
   문서)을 읽어 판정하고, 빈 칸은 그 자체를 결함으로 올린다.
6. **'승인'은 옵션을 고르는 일이지 실행 허가가 아니다 — 실행 전에 세 가지를 본다.** 백로그 항목을 승인받았으면
   ① `approval` 필드가 **이미 채워져 있는지**(다른 역할이 이미 승인받아 `needs_setup` 으로 내려 command 만 기다리는
   경우가 흔하다 — 다시 승인받을 일이 없다) ② 고른 옵션이 **다른 열린 항목과 충돌하는지**(예: '피처 빌더 로드창을
   120거래일로 고정'은 '로드창을 격자와 분리해야 momentum_3_12m 이 산다'는 항목과 정면 충돌 — 실행하면 피처가 조용히 죽는다)
   ③ 선결 지표가 확인됐는지(호출 한도·표본 일수·`not_before`). 하나라도 걸리면 실행하지 않고 **충돌·선결을 숫자와
   코드 위치로 붙여 되돌려 보고**한다.
   백로그 JSON 을 고칠 때는 `json.dump(..., ensure_ascii=False, indent=2)` 후 tmp → `os.replace` 로 원자 교체하고,
   **`result` 필드가 dict 인 항목과 str 인 항목이 섞여 있다** — 문자열 결합 전에 타입을 확인하라(TypeError 로
   종결 기록이 통째로 날아간다). 종결에는 검증한 것과 **미검증(첫 실발화·다음 거래일 발행)** 을 분리해 남긴다.

## 게이트를 확장할 때의 함정 (실측)

- **주석을 코드로 파싱하면 오탐이 난다**: 게이트가 스크립트에서 인자를 추출할 때(예: 승격 문턱) 주석 줄을
  포함하면, 그 파일에 적어 둔 **옛 값이나 설명 문구**를 현재 설정으로 읽어 "위반"을 만든다. 파싱 전에
  `l.strip().startswith('#')` 로 주석 줄을 제거하라.
- **레거시 산출물과 비교하면 오탐이 난다**: 백업 디렉터리 중 오래된 것(단일 분할 운값이 기록된 시절)과 현재
  챔피언을 비교하면 실제보다 큰 회귀처럼 보인다. **비교 가능한 지표 파일(다중 시드 기록)을 우선**하고
  최근 백업만 본다.
- **감사 스크립트는 보유·포지션 유무로 fail/warn 을 갈라야 한다**: "루프가 청산창 뒤에 떴다"는 보유가 0이면
  경고, 보유가 있으면 실패다. 한쪽만 두면 매일 오탐이 나거나 진짜 사고를 놓친다.
- **재사용할 검사는 파라미터화한다**: 모델 A/B 프로브처럼 대상이 바뀌는 도구는 하드코딩 대신 환경변수
  (`PROBE_MODEL_DIRS`)와 **기계가 읽는 요약줄**(`PROBE_SUMMARY {...}`)을 내보내게 해야 릴리스 사전검사가 그대로
  호출할 수 있다.
- **Windows 쪽 파일을 읽는 검사는 경로 형식을 바꿔 넘긴다**: Windows 파이썬에 `/mnt/c/...` 를 주면
  `unable to open database file` 로 죽는다 — `C:\...` 로 넘긴다(저널 읽기).
- **감사 스크립트 자체의 회귀는 테스트로 고정한다**: 루트 `pytest` 가 돈다(컨테스트 모듈명 충돌·`app`
  네임스페이스 선점은 `analyist-dd-stack-ops` 참조). 스택 스모크 규약 `scripts/_*_test.py`(PASS/FAIL 출력 +
  `sys.exit(1 if FAIL else 0)`)도 그대로 쓰인다 — "허용 종료코드 · 산출 JSON 존재 · 필수 키"를 검사한다.
- **부분 실패를 증거로 기록하면 안 된다**: 측정 파트가 입력 파일을 못 찾아 **빈 결과**를 내면 그걸
  '증거 있음'으로 저장하지 마라 — 하류 비교(상관·게이트)가 크래시하거나 판정을 조용히 왜곡한다
  (빈 dict 는 '증거 없음'이지 증거가 아니다). 부분 실패에서도 앞 파트 결과는 저장되게 하고,
  증거 파일은 **끝까지 못 돌아도 쓰이게** 해라(안 쓰면 게이트가 영원히 '증거 없음'으로 승격을 막는다).
- **입력 결측이 검사를 우회하게 두지 마라**: 경과 세션 수를 파일 키에서 세다가 값이 없어 `None` 이 되면
  '아직 이르다' 검사를 건너뛰고 판정해 버린다(가드가 아니라 결함이다). 대체 소스를 명시하고(예: DB 의
  거래일 수), 대체도 실패하면 **'판정 불가'로 남긴다** — 결측은 '통과'가 아니다.

## 자율 루프의 목표·게이트·되돌림 (자율 개선 구조)

사람 없이 돌게 하려면 목표·봉투·게이트를 **문서가 아니라 기계가 읽는 파일**로 고정하고, 판단을 게이트로 옮긴다.
구체 스키마·명령은 `references/autonomy-objective.md`.

1. **목표는 한 파일에서 온다**: `config/objective.json`(지표·프로토콜·수용 기준·봉투·게이트 정책) +
  `scripts/objective.py`(스키마 검증 · `--envelope-drift` · `promote-flags`). 게이트 임계값을 코드에 복사하지 말고
  **파이프라인이 이 파일에서 인자를 생성해** 게이트에 넘겨라(정책과 코드가 조용히 어긋나는 것을 막는다).
2. **봉투(위험 한도)의 소스 오브 트루스는 트레이더 설정**이고 objective.json 은 사본이다 — 둘을 대조하는
  드리프트 검사를 게이트에 포함하라(사본이 늓으면 루프 전체가 잘못된 한도 위에서 돈다).
3. **매일 상태 한 장**: `data/state/objective_state.json`(목표 지표 현재값·돈·봉투 위반·1순위 손실원·신선도).
  루프·경보·아침 보고는 여기만 보고, 봉투 위반은 *바뀔 때만* 알린다(같은 경보 반복은 상태파일로 침묵).
4. **새 게이트는 기본 OFF 로 배선하고 한 줄로 켜라**: 측정·계기판·감사·경보는 완전 자율(T0),
  모델·파라미터·선택규칙은 사전등록 증거 게이트 + 자동 되돌림이 있을 때만 자율(T1),
  봉투 값·주문 경로·킬스위치 의미·자격증명은 사람(T2). **T1 을 열기 전에 T1 의 되돌림 장치가 먼저 있어야 한다.**
5. **되돌림은 '증거 없음'을 원복 사유로 쓰지 않는다**: 승격 후 K세션 뒤 같은 프로토콜 증거로 재비교하고,
  증거가 없거나 늘어졌으면 **판정하지 않는다**(근거 없이 챔피언을 흔들면 진동한다). 3D·디바운스·보수적
  임계·실행 로그·스왑 로그 기록을 갖추고, 실행은 게이트 하나로 켜고 끈 수 있게 둔다.
6. **비교는 같은 프로토콜 값끼리만**: 후보·챔피언·백업의 증거를 같은 스크립트·같은 창·같은 라벨로 측정해
  같은 파일 형식으로 남긴다. 서로 다른 프로토콜의 숫자를 나란히 놓으면 부호까지 뒤집힌다.
7. **개선 큐·오케스트레이터 = 자율 병합은 경계 안에서만**: 야간에 큐에서 1건을 꺼내 worktree 에 위임 →
  기계 검증(구문·테스트·루트 pytest) → 통과 시 **과제당 1커밋**으로 병합한다. **병합 금지 경로**
  (실주문 경로 `trader-agent/`, 라이브 파이프라인, 승격 게이트 본체, 정책 값 `config/objective.json`,
  자격증명·킬스위치, 게이트 임계 스크립트)를 건드린 변경은 검증 통과 여부와 **무관하게** `needs_human`
  으로 끝낸다 — 경계는 프롬프트 지시가 아니라 **디스패처의 경로 검사로 강제**한다. 큐 스키마·디스패처
  절차·보호 목록은 `references/improve-orchestrator.md`.
8. **자율 병합은 dry-run 을 먼저 통과시킨 뒤 켠다**: 게이트 기본 OFF 로 두고 먼저 '검증·보고만'으로
  며칠 돌려 위임·검증·기록이 실제로 도는지 확인한 뒤 T0(측정·테스트·문서·감사·틱)만 자동 병합으로 올린다.
  중단은 **파일 하나**(`data/state/improve_pause`)로 즉시 되게 두고, 과제 2회 실패는 사람 대기로 고정한다.
9. **자율 탐색(T1)은 사전등록 격자로만, 체결성은 축이 아니라 전제조건**: 탐색을 붙일 때는 재학습이 필요 없는
  파라미터(선별 깊이·체결성 필터·청산 규칙)를 돈 지표로 평가하는 러너부터 쓴다(호스트 측이라 싸고 되돌리기 쉽다).
  격자와 수용 기준을 **코드/objective.json 에 미리 등록**하고(사후 축 추가 = p-hacking), 비교 기준선은 같은
  데이터 안의 현행 조합으로 잡는다(외부에서 잰 챔피언 값과 섞으면 부호가 뒤집힌다). **체결성 필터를 축으로
  두면 '살 수 없는 상한가' 조합이 통과하는 착시가 난다** — 격자에서 빼고 판정에도 가드를 둔다(2중 방어).
  통과 조합은 실주문 경로를 바꾸므로 자동 반영하지 않고 `protected` 제안으로 큐에 넣는다. 통과가 없으면
  (=대부분의 날) 조용히 기록만 남긴다. 레시피·실측값 `references/autonomy-objective.md` §6.
