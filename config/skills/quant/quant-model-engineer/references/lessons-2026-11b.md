## 2026-11-25 — 청산 호라이즌 스윕은 '대조군 대비' 판정기로 돌려라 (CG486)

- **스윕 요약(`fillable_topk_horizon_sweep`)을 `fillable_topk_vs_pool` 로 판정하면 널이 '세션 풀평균'이
  되어 사전등록 문턱(대조군 대비 Δ)을 못 본다.** 실측: 같은 두 덤프가 풀 대비 Δ+1.2~+1.6(t 3.2~4.8)
  = '신호'인데, 챔피언 대비 비중첩 Δ+1.158(t 1.63)/+0.697(t 0.67) = 문턱 미달. 판정기 metric 은
  반드시 `success` 문구의 '무엇 대비 Δ' 와 일치시켜라. 불일치 상태로 돌린 회차는 원장 자동판정을
  믿지 말고 수동 재판정해 `backlog.result` 를 덮어쓴다.
- **호라이즌 판정은 비중첩(stride=h)만 인정하고 표본 n≥40 을 요구하라.** stride=1 로 h3/h10 을 재면
  t 가 겹친 창 재사용으로 부풀고(예 h10 t 3.82 → 비중첩 1.26), 비중첩 표본은 255→85(h3)/55(h5)/30(h10)
  으로 줄어 t<2 가 흔하다. h10 통과(n=30)로 '보유기간이 원인'을 주장하면 트레이더 보유(≤5일) 밖 축을
  근거로 쓰는 셈이다.
- **수리된 배선**: sweep JSON `horizon_table` 에 `arm_minus_control`·`_t`·`_n` 과 호라이즌별 `stride` 를
  싣고, 판정기 `judge_fillable_horizon_paired`(metric=`fillable_horizon_paired`, `judge_thresholds`
  ={delta,t,horizons,min_n}) 를 추가했다. 중첩·표본부족 셀은 통과로 세지 않고 ⚠ 로만 표시된다.
- **부수 실측(트레이더 전달값)**: 배포 챔피언은 h10 에서 풀 −1.7~-2.1%p/세션으로 보유가 길수록 더 나쁘고,
  재학습 arm 대비 격차도 h1 에서 0(Δ+0.05/−0.02/+0.02)이다 → 챔피언의 엣지가 있다면 짧은 보유에 몰려 있다.

## 2026-11-25 밤 (CG486~CG489) — 겹침 t 팽창 · 판정기 라벨 함정 · 베타 귀속

- **h>1 돈 실험은 stride1 t 를 절대 인용하지 말라 — 점추정은 같고 검정만 부푼다.** 실측: LS_quant_q30_h5
  k3 h5 Δ +1.208%p/세션의 stride1 t 3.21 은 비중첩(stride=5)에서 t 0.67(n 55)로 붕괴, h10 도 3.82 → 1.26.
  해법은 두 가지를 **둘 다** 병기: ① `--stride h` 재채점 ② 이동블록 부트스트랩 t(`--overlap-block`,
  `cg281_beta_attribution --block-boot`). 블록t 로 다시 재면 같은 Δ 의 t 가 3.21 → 2.10 이다.
- **판정기에서 `halves['stable'] == "stable"` 로 비교하면 실측이 뒤집힌다.** `fillable_topk_expectancy.halves()`
  는 `"both_positive" | "unstable" | "neither"` 를 준다(`"stable"` 이라는 값은 없다). 이 버그로 CG488 이
  22:21 회차에 '노이즈'로 원장에 남았고, 라벨을 고치자 같은 JSON 이 '신호(intercept +1.04, 블록t 2.10,
  분할 both_positive)'로 판정됐다. **새 판정기를 쓸 때 라벨 문자열은 소스에서 확인**하고, 첫 실행의
  판정 문구에 '미달 사유'가 실제 수치와 모순되면 그건 판정기 버그다(수치 탓이 아니다).
