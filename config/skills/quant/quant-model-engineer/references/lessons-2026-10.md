## 2026-10-10 (4) — 승인용 패치의 apply-check 는 '대상 레포별'로 검증하라

- **사각**: 승인 패킷에 "패치 5종 `git apply --check -p1` 전부 rc=0" 이라 적었는데, 실제로는 메인 레포에서
  **4종만** rc=0 이고 mt189(`runner/config.py`)는 'No such file or directory' 로 실패했다 — 대상 레포가
  trader 레포라서 실패가 정상인데, 한 레포에서 뭉뚱그려 재면 "패치가 깨졌다"와 "레포가 다르다"를 구분하지
  못한다. 승인 직전 이 오표기는 사람이 엉뚱한 레포에 적용하거나 승인을 보류하게 만든다.
- **규칙**: `data/reports/*.patch` 는 **대상 레포가 제각각**(분석=analyist_dd · MT189=trader-agent ·
  L5c=strategy-agents)이다. 검증표를 `패치 | 대상 레포 | apply-check` 3열로 적고, 각 패치는 **그 레포에서**
  `git apply --check -p1` 을 돌려 rc 를 적어라. 메인 레포에서의 실패는 무효 신호로 취급한다.
- 실측(2026-10-10 21:0x): 메인 4종 rc=0(cg131·cg135·xr26·l5c) · mt189 → `cd trader-agent && git apply

### 같은 날 후속 — "N폴드"가 실제로는 1창이 되는 함정
