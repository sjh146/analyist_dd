# autonomous-improvement-loop — 무인 개선 루프 (찾고 → 검증하고 → 반영한다)

For the class of task "make the system improve itself while nobody is watching": a nightly loop that
picks work from measured defects, delegates or scripts the change, mechanically verifies it, and
merges only what passes a pre-registered gate. Read this before building, extending, or debugging
such a loop, and before trusting its output.

Two halves, and the loop is only as good as the weaker one:
- **탐색(찾는 쪽)** — 사전등록된 격자를 돈/성과 지표로 매일 재평가한다. §1.
- **반영(고치는 쪽)** — 위임 → 검증 → 과제당 1커밋 → 게이트 통과분만 병합. §2.

## 0. 먼저 고정할 것

1. **목표를 기계가 읽는 단일 진실원으로 만들어라**(예: `config/objective.json` — 지표·프로토콜·수용 기준·
   봉투·게이트). 루프가 "좋아졌다"를 스스로 판정하려면 사람의 서술이 아니라 파일이어야 한다.
2. **조정 가능한 것과 아닌 것을 코드로 나눠라.** 봉투(한도)·계약·실주문 경로·자격증명은 루프가 못 건드린다.
   문서로만 막은 경계는 지켜지지 않는다 — 위임 프롬프트에 '건드리지 말라'고 써도 위반한다.
3. **수용 기준은 게이트 코드와 같은 값에서 읽어라**(기준을 두 곳에 쓰면 반드시 갈라진다).

## 1. 탐색 절반 — 사전등록 격자

- **격자는 코드에 사전등록**하고, 새 축·조합은 커밋으로 남긴다(사후 조정 = p-hacking). 격자가 바뀌면
  registry 를 새 프로토콜 해시로 초기화하고 구 격자 결과와 섞지 않는다.
- **스킵 키에 '데이터 지문'을 넣어라.** 조합 키만으로 건너뛰면 첫 실행 뒤 새 데이터가 쌓여도 전 조합이
  '이미 평가됨'이 되어 **매일 no-op** — 탐색이 이름만 남고 죽는다(스스로 발견한 결함). 지문 = 대상 파일의
  (크기, mtime, 그룹 수) 등 그 수치가 의존하는 것.
- **조정 대상이 아닌 제약은 격자에서 빼고 판정 코드에서도 막아라(둘 다 필요).** 예: 체결성(살 수 있는가)은
  탐색 축이 아니라 전제다 — 축으로 남기면 무제약 슬라이스가 '통과'로 올라온다(실측: 무필터 +5.23%p vs
  필터 −0.67%p, 같은 데이터). 한쪽만 고치면 다른 쪽으로 재발한다.
- **반전·대조군을 사전등록하라.** 랭킹 키를 뒤집은 조합을 같은 격자에 넣는다 — 뒤집은 쪽이 더 좋으면
  그 키는 이 후보 집합에서 **반예측**이다(실측: 점수 하위 −0.134%p > 상위 −0.286%p). 통과/불통과보다 이
  신호가 '키를 고칠지 말지'를 먼저 말해준다. 대조군 없는 Δ 는 판정이 아니다.
- **공집합·퇴화 부분집합은 '측정 불가'지 0 이 아니다.** 필터 적용 후 행이 0이면 그 사실과 이유를 보고한다
  (실측: 후보 1,736행 중 게이트 통과 0행 → 현행 경로가 산 집합이 공집합). 필터가 입력 컬럼을 못 찾을 때도
  '통과분'을 주장하지 말고 빈 집합을 돌려준다 — 조용한 0건은 시장이 조용한 것처럼 보인다.
- **매 실행 판정을 로그·registry 에 남기고, 통과가 있을 때만 알린다.** 대부분의 날은 침묵이 정상이다
  (침묵을 '고장'으로 오진하지 않도록 실행 흔적은 반드시 남긴다).
- **검증이 끝난 과제와 통과 조합은 '제안(protected)'으로 큐에 넣고 상태를 닫아라.** 실주문·계약을 바꾸는
  발견은 자동 반영 대상이 아니다 — 자동인 것은 '증거를 만드는 일'까지다.

## 2. 반영 절반 — 위임·병합

1. **큐는 측정된 손실원에서만 만든다.** 억지 과제를 생성하면 루프가 자기 잡음으로 채워진다. 같은 출처+
   같은 이유면 1건으로 합친다(제목만 다른 중복이 곧바로 생긴다).
2. **작업은 격리된 worktree 에서** 하고, 위임 프롬프트에 목표·근거·금지 경로·산출물 형식을 명시한다.
3. **병합 전 검사 3종**: ⓪ 금지 경로 접촉(1줄이라도 닿으면 `needs_human`) ① 위임 검증 스크립트 ② 루트 테스트.
4. **과제당 1커밋 + 되돌리기 명령을 남긴다**(`git revert <sha>`). 커밋이 여러 개면 자동 원복이 불가능해진다.
5. **위임 결과는 '내용'으로 판정하라 — rc=0 은 성공이 아니다.** 실측: 1차 백엔드가 rc=0 + 0바이트를 냈고
   폴백이 실제 작업을 했다. 산출물이 비었으면 실패로 처리하고 폴백/재위임한다.
6. **위임 잡음은 커밋에서 제외하라.** stderr 덤프·백엔드 마커·로그가 트리 오염으로 딸려 들어온다 →
   `git add -A` 뒤 그 pathspec 을 `git reset` 하고 `.gitignore` 에도 등록한다(실측: 754줄 stderr).
   이미 푸시된 커밋에 들어가면 amend 가 force-push 를 요구하므로 **병합 전**에 걸러야 한다.
7. **긴급 정지는 파일 1개**(예: `touch data/state/improve_pause`) — 사람이 끼어들 수 있는 저비용 레버다.
8. **사람 검토가 끝난 과제는 상태를 `merged` 로 닫고 근거(커밋)를 남긴다.** 모호한 "승인할게" 는 승인이 아니다.

## 3. 이 루프를 고칠 때 (함정)

- **정책값을 박아둔 테스트는 정책을 바꾸면 같이 깨진다.** `auto_merge: false` 를 단언하는 테스트는
  검증 후 값을 켜는 순간 실패한다 — 값이 아니라 **타입/행동**을 잠그거나 정책 테스트와 행동 테스트를 분리한다.
- **달력·상태 파일에 의존하는 테스트는 시간 무관하게 만들어라**(스케줄 함수를 고정하거나 주말·휴장 케이스를
  명시). 안 그러면 주말마다 빨간불이 뜨고 다음 사람이 코드 회귀로 오진한다.
- **탐색 도구와 판정 도구는 같은 모듈을 재사용하라**(지표 계산을 복사하면 두 숫자가 갈라진다). 무거운
  로딩은 1회로 두고 축만 바꿔 도는 것이 격자 평가의 기본 모양이다.
- **루프의 자기 보고를 믿지 말고 흔적을 읽어라**: registry mtime·원장 JSONL·커밋 로그·크론 실행 DB
  (status + delivery_outcome 짝). '실행됨'과 '전달됨'은 다르다.

## 4. 보고 규칙

- 사용자 언어로 **결과 → 실측 수치 → 남은 한계** 순서. 통과 0개도 정직한 결과다(오히려 그쪽이 대부분).
- 루프가 스스로 발견한 결함은 '무엇을 잘못 판정했고 왜인지'까지 함께 보고한다 — 그게 루프의 신뢰도 증거다.
- 사람 몫(로그인·봉투 값·킬스위치 재개)은 항상 별도 항목으로 분리해 명시한다.
