# 챔피언 모델 학습·검증 운영

대상: analyist_dd 계열 스택의 방향 예측 모델(챔피언 = xgboost+lightgbm+catboost 앙상블).
스크리너·피드가 이 모델을 라이브 추론 계약으로 읽으므로 **후보 디렉터리에 학습하고 게이트를 통과할 때만 승격**한다.

## 0. 절대 규칙

- `app/models/champion` 을 손으로 덮어쓰지 않는다. 승격은 `app/training/champion_promote.py`(게이트·백업)로만 한다.
- 성능은 **멀티시드 평균±std** 로 보고한다. 단일 시드 최고값으로 승격을 판단하지 않는다.
- 못 넘겼으면 못 넘겼다고 보고한다(달성치·근거·한계). 검증되지 않은 시도 나열을 "권장 절차"로 쓰지 않는다.
- 측정이 경합 상태였으면 그 라벨을 숫자 옆에 남긴다 — 경합 중 수치를 정상치처럼 보고하지 않는다.
- 개선 판정은 '같은 설정의 before' 만 보지 않는다: **지금까지의 최고 베이스라인**(설정이 다른 값 포함)과 나란히 놓는다.
  같은 설정 대비 +0.008 이어도 최고 베이스라인보다 낮으면 "개선"이 아니라 노이즈다(실측: 뉴스 on 0.5191 vs 뉴스 없던 동일설정 0.5112 이지만, 뉴스 없는 최고 조합은 0.5205).

## 1. 수명주기 (명령 순서)

1) **후보 학습** — 컨테이너 cwd `/app`:
   `python -m app.training.retrain_champion --days <N> --stock-limit <M> --out-dir app/models/<후보>`
   → 후보 dir 에 `feature_names.json`(canonical 순서), `auc.txt`, `training-result-<ts>.json` 이 함께 쓰인다.
2) **하네스 교차검증** — `scripts/phase_4_backtest.py --model-dir <dir> --days 90 --out <json>`
   (층화 랜덤 50종목 · 최근 90거래일 OOS AUC). **현 챔피언을 먼저 재측정**해 파이프라인 인라인 백테스트 값과 ±0.01 내 일치를
   확인한다(측정 도구 자체 검증). 어긋나면 그 뒤 후보 비교는 무의미하다.
3) **게이트 승격** —
   `python -m app.training.champion_promote --candidate <후보> --champion app/models/champion --min-auc 0.55 --legacy-baseline-cap 0.55 --max-std 0.05 --summary-out app/reports/ml_result.json`
   게이트: ① 후보 지표(`auc_mean` 있으면 그것, 없으면 `ensemble_auc`) ≥ 바닥값 ② 그 지표 ≥ **챔피언 기준선**
   ③ 후보 `auc_std` ≤ `--max-std`(멀티시드 변동이 큰 후보 거부). 기준선은 `champion/robust_auc.json`(승격 시 기록)이
   있으면 그 값, 없으면 `min(auc.txt, --legacy-baseline-cap)` — **디스크에 남은 단일 시드 값과 그대로 비교하면
   과거의 운값이 승격을 영구히 잠근다**(실측: 같은 코드·데이터로 0.44↔0.61 요동 → 그 운값이 기준선이 되어
   walk-forward 0.54~0.58 로 개선된 후보가 계속 거부됐다). 승격 시 `robust_auc.json` 을 함께 써서 다음 비교가
   같은 기준이 되게 한다. 산출물 누락·`auc.txt`↔training-result 불일치는 invalid 로 거부.
   승격 시 직전 챔피언이 `champion_prev_<ts>` 로 자동 백업 → 되돌리기는 그 디렉터리를 `champion` 으로 복사.
   **게이트를 바꿨으면 실행 전에 dry-run 으로 실후보 4케이스(하한 미달 / 옛 게이트에서 막히던 후보 = 잠금 해제
   증거 / 기준선 파일 우선 / std 초과 거부)를 검증**하고, 라이브 요약을 덮어쓰지 않게 `--summary-out /tmp/...`
   을 쓴다.
   **기준선을 정하려고 새 모델을 학습해 견주지 마라 — 배포 모델을 직접 재평가**한다
   (`scripts/champion_robust_eval.py` + 챔피언 디렉터리 스냅샷 후 `--write`). 이 원칙(견고 기준선·스냅샷·
   dry-run 검증)은 스택 밖에도 적용된다 → `trading/ml-model-validation-promotion`.
4) 야간 파이프라인 Phase 2 는 "후보 학습 → 게이트 승격"만 해야 한다. 스모크/검증 스크립트가 챔피언 디렉터리에 쓰면
   그 자체가 사고다(수 종목 스모크 모델이 라이브 챔피언을 대체할 수 있다) — 스모크 산출물은 별도 디렉터리로 보낸다.

## 2. 검증 규칙 (단일 split 금지)

- val AUC 는 재현되지 않는다: 같은 데이터에서 수집량만 달라져도 0.44↔0.61, 그리고 val 0.61 → 최근 90거래일 OOS 0.49 를 실측했다.
- 채택은 3종을 모두 본다: 멀티시드 평균±std(val/test) · 워크포워드 평균 · OOS. OOS 가 현 챔피언보다 나쁘면 승격하지 않는다.
- 학습 스크립트가 `--seed`/`--n-estimators` 를 실제로 모델 생성자에 넘기는지 먼저 검증한다. 모델 클래스는 하이퍼파라미터를
  `__init__` 에 하드코딩하므로, 안 넘기면 CLI 실험이 무효이고 멀티시드 측정 자체가 불가능해진다.
- `Trainer.prepare_training_data` 반환값 개수(현재 7개)를 시그니처에서 확인하고 unpack 한다 — 개수가 바뀌면 학습 스크립트가 즉시 죽는다.

## 3. 야간 실험 캠페인 운영

- **데이터 고정**: 수집 크론(분봉·백필)을 먼저 멈춘다 — `/etc/cron.d/<file>` 을 점 포함 이름으로 rename(`...disabled`).
  cron 은 파일명에 `.` 이 있는 파일을 파싱하지 않는다. 복구는 rename 되돌리기 한 줄, 원본은 `/home/<user>/cron/` 에 백업.
  밤사이 수집이 들어오면 패널 캐시와 AUC 비교 기준이 바뀐다.
- **피처 캐시**: 피처 빌드 비용은 **피처 계약 수에 따라 달라진다** — 173피처 시절 종목-일 쌍당 약 0.08초였으나
  **199피처(+Neo4j 그래프·SNS·매크로 as-of 호출)에서는 약 0.45초**로 측정됐다 → 200종목×120일(16,080쌍) ≈ **2시간**.
  캠페인 시작에 1회 빌드해 디스크 캐시로 저장하고(키에 종목수·기간·**마지막 거래일** 포함) 이후 실험이 재사용한다.
  캐시 없이 실험마다 재빌드하면 하룻밤에 몇 개 못 돈다. **피처를 부활시킨 뒤에는 이 비용과 모든 타임아웃 예산을 다시 계산하라.**
  - 캐시 키에 격자·기간·마지막 거래일뿐 아니라 **행 집합 지문**(요청한 (종목,날짜) 집합의 해시)을 넣어라 — 크로스섹션 랭크 주입은 그 날의 종목 집합에 의존하므로, 같은 기간이라도 종목 집합이 다르면 재사용이 값을 바꾼다.
  - **HIT/MISS 를 항상 로그에 남겨라**(조용한 재사용 금지). 저장은 tmp 쓰고 원자적 교체, 손상 캐시는 버리고 재빌드, 탈출구(`--no-panel-cache`)를 둔다. 데이터 지문을 못 얻으면 캐시를 끈다(안전).
  - **캐시가 값을 바꾸지 않았음을 증명하라**: 같은 행 집합을 ① 캐시 없이 신규 빌드 ② 캐시 저장 ③ 캐시 재로드 로 돌려 **피처 해시 3자가 같은지** 비교한다(`scripts/_panel_cache_fidelity_probe.py`). 작은 격자를 두 번 돌려 지표를 눈으로 보는 방식은 그 격자가 값을 못 내면(전부 None) **아무것도 검증하지 못한다** — 지표 대신 객체 해시로 검증하라.
  - 후보(매일)와 챔피언 기준선(주 1회)이 **같은 행 집합**을 쓰면 두 번째 호출은 정의상 HIT 다 — 월 1회 ≈13분 절감이 여기서 나온다.
- **먼저 유니버스 선택 SQL 을 읽어라 — 성능을 지배하는 것은 피처가 아니라 표본 수다.** 기본 선택 쿼리가
  `WHERE market='<한 시장>' … ORDER BY stock_code LIMIT <N>` 형태면 **알파벳 앞 N개**만 학습한다(실측: 패널
  13,609행/49종목인데 DB 에는 약 3,900종목×15개월=108만행이 있었다). 유니버스를 옵션으로 늘릴 때는
  **기본값을 현행 그대로 두고**(비교가능성) 옵션을 추가한다 — `market`(비우면 시장 제한 해제) · `since` ·
  `min_days` · `min_value`(일평균 거래대금 하한) · `order`(code=현행 알파벳순 / value=거래대금 상위).
  검증은 **패널을 빌드하기 전에 DB 조회만으로**: ① 기본값 호출이 기존 패널 종목과 전부 교집합인지(하위호환)
  ② 확장 호출이 여러 시장을 유동성 상위로 뽑는지. **패널 캐시는 파일명으로만 구분**되므로 유니버스를 바꿀 때는
  **새 파일명**을 써라 — 기존 패널을 덮으면 대조군이 사라진다.
- **패널 빌드 견적은 종목 수가 아니라 종목-일 쌍 수로 계산한다**: 199피처 계약에서 실측 **0.53초/쌍**.
  150종목×281일 ≈ 4.2만쌍 ≈ 6시간, 500종목 ≈ 14시간. 14시간짜리 단일 빌드는 컨테이너 재시작 1회로 전부
  소실되므로 **작은 유니버스로 신호를 먼저 확인하고 단계적으로 확장**한다(150 → 500).
- **학습 타임아웃은 패널 빌드 비용보다 크게 잡아라**: 예산이 부족하면 후보가 완성되기 전에 죽어
  (`exit=124`) **승격 심사가 아예 열리지 않는다** — 게이트가 막은 것과 전혀 다른 사건인데 로그에는 둘 다
  "승격 안 됨"으로 보인다(실측: 30분 예산에서 4,000/16,080쌍에서 중단). 규모(`--days`/`--stock-limit`)를
  바꾸면 `timeout` 을 함께 조정하고, RC=124 를 전용 문구로 남겨 다음 세션이 오진하지 않게 한다.
- **파이프라인 요약줄의 AUC 는 후보 값이 아닐 수 있다**: 최종 로그의 `Best AUC: <값>` 류는 보통 **라이브 모델의
  저장값**(`auc.txt`)이다. 후보 판정은 승격 요약 JSON(`status`/`reason`/`candidate_metric`)으로 하고,
  `decided_at` 이 옛 날짜면 그 회차 승격 단계가 아예 실행되지 않은 것이다.
- **자격증명이 없는 수집 단계는 스크립트에서 사전에 건너뛴다**: 로그인 전제 수집기를 자격증명 없이 돌리면
  **종목마다** 실패 줄을 찍어 로그를 수천 줄로 채우고 시간을 버린다(실측 9,000여 줄) → 자격증명 존재를
  확인하는 조건문으로 감싸고, 건너뛰었다는 사실과 사유를 로그에 남긴다.
- **직렬화**: 한 번에 실험 1개, 프로세스당 `OMP_NUM_THREADS=2`. 4코어에서 무거운 작업을 겹치면 처리량이 급락한다
  (임베딩 스레드 4가 스레드 1보다 3배 느려진 실측). 실험 큐·조기종료 게이트·마감 규칙을 담은 드라이버를 detached 로 돌린다.
- **드라이버 규약**: `heartbeat.txt`(2분 주기) · `results.jsonl`(실험별 시드 AUC·평균·std·OOS 1줄) · 실험별 로그 ·
  `FINAL_REPORT.md` · `done.flag`/`gate_passed.flag`. "새 실험 시작 금지 시각"과 "최종 리포트 시각"을 상수로 박는다.
  실험별 try/except, DB 실패 시 대기 후 1회 재시도, 메모리 부족 시 패널 크기 축소.
- **먼저 스모크**: 큐 첫 실험을 축소 파라미터(시드 2개·기간/종목 축소)로 끝까지 돌려 문법·경로·산출물·승격 dry-run 을 검증한 뒤 본 실행한다.
- **감시**: heartbeat mtime 이 15분 이상 멈추면 정지로 판단한다. 완료 마커를 기다리는 watcher 를 걸어 두면 완료·게이트 통과 시점에 깨어난다.
- **다음 작업을 앞 작업 종료에 체인할 때 `pgrep -f '<스크립트명>'` 으로 기다리지 마라.** 대기 셸 자신의 명령줄에
  그 패턴 문자열이 들어 있어 **자기 자신과 매칭되므로 영원히 기다린다**(실측: 1.7시간 무한 대기, 후속 스윕이
  시작되지 않았고 로그 파일조차 생기지 않았다). `kill -0 <PID>` 로 기다리거나, 앞 작업이 끝에 남기는
  마커/산출물 파일의 존재를 기다린다. 체인을 걸었으면 **시작됐는지 확인**한다(로그 파일 유무) — 안 생겼으면
  대기 조건을 의심하고 직접 격발한다.
- 다른 작업의 프로세스를 죽여야 할 때는 컨테이너 네임스페이스까지 확인한다 — 호스트의 `docker exec` 클라이언트만 죽이면
  컨테이너 안 프로세스는 계속 돌아 CPU 를 먹는다(`docker top` 은 호스트 PID 를 보여준다).
- **두 번째 웨이브는 드라이버를 새로 쓰지 말고 기존 드라이버를 import 해서 만든다.** 드라이버에는 `if __name__ == "__main__"`
  가드가 있어 import 만으로는 main 이 돌지 않으므로, 새 진입 스크립트가 그 헬퍼(데이터 로드·5시드 학습·게이트/승격·heartbeat)를
  그대로 재사용하고 실험 목록과 결과 파일만 자기 것으로 쓴다(자기 `*.jsonl` 에 append). **다른 웨이브가 돌고 있는 드라이버
  파일은 수정하지 않는다** — 수정하면 그 웨이브의 다음 실험부터 코드가 바뀌어 before/after 비교가 깨진다.
  새 웨이브도 `--smoke` 축소 실행으로 문법·경로·산출물을 먼저 검증하고, 본 실행은 `docker exec -d <컨테이너> sh -c 'cd /app && OMP_NUM_THREADS=2 python -u scripts/<wave>.py > <log> 2>&1'` 로 띄운다.
- **감시·재기동은 크론으로 자동화한다.** 마감(예: 06:15 KST)이 있는 반복 루프는 30분 주기 자체완결 크론 프롬프트에
  ① `pgrep -af <wave>` 로 생존 확인 ② 죽었고 다음 웨이브 결과가 아직 없는 상태에서 마감 전이면 다음 웨이브를 기동
  ③ 마감 후면 최종 요약만 ④ 금지 목록(형제 실험 프로세스 종료·유료 호출·커밋/푸시·컨테이너 재기동)을 넣고, 보고는 한국어 3~6줄·실측값만.
  사용자는 장시간 자율 작업 중 짧은 중간보고를 기대한다.
- **캠페인 도중에 입력 테이블을 채우지 않는다** — 실험마다 패널을 DB 에서 다시 빌드하므로 중간에 채운 데이터가 앞뒤 실험의
  피처를 바꾼다(§3 데이터 고정과 같은 이유). 채울 거면 캠페인 시작 전이나 종료 후에 하고, 불가피하면 결과에 라벨을 남긴다.
- 드라이버가 만든 결과·로그 파일은 컨테이너 root 소유라 호스트 사용자가 덮어쓸 수 없다 — 정리·수정은
  `docker exec <컨테이너> sh -c 'grep -v ... /app/reports/... > /tmp/x && cat /tmp/x > /app/reports/...'` 로 한다.

### 장중 경계 — 오래 도는 실험은 장 시작 전에 밖에서 멈춘다

- 위 드라이버류의 가드는 **'시작'만** 막는다(장중 시작 금지 + `est_minutes` 로 다음 컨테이너 재생성(평일 20:00)을
  넘는 시작 금지). 이미 도는 20시간짜리 작업(예: 확장 이력 패널 빌드, 실측 0.42 쌍/초)을 멈추는 장치는 없다 →
  주말 저녁에 시작하면 **월요일 장중을 그대로 관통**해 08:30 스윙 파이프라인·08:40 피드 발행과 4코어를 다툰다.
  사용자 정책은 "장중엔 트레이더·피드가 CPU 우선".
- 그래서 긴 작업을 재개할 때는 **개장일 여부(`data/krx_holidays.json`)를 먼저 확인**하고, 개장일이 끼면
  장 시작 전(예: 08:05) 정지시키는 1회성 예약을 함께 건다.
- 대상을 **argv 로 좁혀** 고른다: `docker top <컨테이너> | awk '/wf_label_sweep/ && /panel_995\.npz/ {print $2}'`.
  패턴을 넓게 잡으면 **동시에 돌던 다른 실험까지 죽는다** → 정지 스크립트는 dry-run 으로 "지금 도는 다른 실험은
  매칭 0"을 먼저 확인하는 형태로 만들고, 예약 전에 그 dry-run 을 실제로 돌려 확인한다.
- 정지: `/mnt/c/Windows/System32/wsl.exe -u root -- kill -TERM <pids>` → 5초 → 잔존 시 `-9`
  (컨테이너 프로세스는 호스트에서 root 로만 죽는다). 손실은 체크포인트 간격뿐이다(예: 500쌍 ≈ 20분).
- **정지하고 끝내지 마라 — 재개가 장중에 일어나지 않게 만들어라**: 진행률·실측 속도로 남은 시간을 계산해 백로그의
  `est_minutes` 를 하향한다. 그러면 ETA 가드가 "지금 시작하면 다음 재생성 창을 넘는다"로 막고 야간 창까지 기다린다
  (원래 est 를 두면 저녁 22:00 시작이 허용돼 다음날 장중을 먹는다).
- 1회성 예약은 Hermes 크론 `no_agent` + `script` 로 건다. **`script` 는 `~/.hermes/scripts/` 아래 상대경로만 받는다**
  (절대경로 거부) → 리포 스크립트를 `exec` 하는 얇은 래퍼를 만들고 파일명만 넘긴다. 일시 예약은 KST 벽시계
  ISO(`schedule='2026-09-28T08:05:00'`)를 그대로 받는다. CLI 세션에서 만든 잡은 `deliver='origin'` 이면
  어디에도 안 가므로 `deliver='all'` 로 건다.

## 4. 데이터·피처 현실 (실측)

- canonical 피처 173개 중 실제로 변동하는 것은 50~60개. 뉴스/수급/매크로 테이블이 비면 대부분 상수 0이 된다.
- 그러나 "테이블 0행 = 피처 죽음"은 아니다: `sentiment_avg`, `news_count_5d`, `similar_stocks_return_avg/std`,
  재무(`net_income`·`revenue`·`op_margin`)는 값을 낸다. 반대로 `authenticity_avg` 는 0.0, `avg_similarity_top10` 은 1.0 상수다.
- 확인 방법: 컨테이너에서 `FeaturePipeline(pg_conn=pg).build_features(code, date)` 결과 dict 의 키별 값과 `feature_count`(실측 167/173)를 찍는다.
  `rank_*` 는 배치 빌드에서만 채워지므로 단일 종목 조회에서 None 인 것이 정상이다.
- **죽은 피처 전수 조사는 2단계로 한다**: ① 입력 테이블을 한 번에 나열 `SELECT relname, n_live_tup FROM pg_stat_user_tables ORDER BY 1`
  → 0행 테이블이 죽은 피처 그룹의 범인 후보다. ② `feature_coverage(feature_name, nonzero_ratio, std)` 로 3분류 — 전부 0 /
  **값은 있으나 `std=0`(상수 → 분기 불가)** / 명목상 살아있음(라이브 크론이 만든 며칠치만 있어 `nonzero_ratio` 1~2%).
  실측 스냅샷(173피처 계약 시점): 97개 전부 0 · 6개 상수(`avg_similarity_top10`, `pbr_percentile`, `quality_f_score`, `similar_count` 등) · 정보 있는 것은 70개 — 이후 백필로 줄었다.
  `nonzero_ratio>0` 만으로 "살아있다"고 세지 말고 `std` 를 함께 본다.
  * **수치를 인용할 때는 스냅샷 시각과 행 수(= 당시 피처 계약 수)를 함께 말하라.** 캐시가 파이프라인 패치
    이전 상태면 현재값이 아니고, 피처 계약 수와 행 수가 다르면 그 스냅샷은 낡은 것이다.
  * **재계산은 컨테이너 안에서**: `docker exec stock_xgboost_ml sh -c 'cd /app && python scripts/feature_coverage_report.py --ignore-cache --stocks 15 --days 20'`.
    호스트 python3(venv 포함)에는 `app` 패키지가 없어 `ModuleNotFoundError: No module named 'app'` 로 즉사한다
    — 진단·평가 스크립트는 전부 컨테이너 안에서 돌린다(재계산은 900 종목-일 피처 빌드라 비싸므로 먼저 캐시를 읽는다).
  * **199피처 계약 기준 스냅샷**: 죽은 55 / 상수 56 / 살아있음(`nonzero_ratio≥0.1`) 133.
    남은 죽은 피처의 배분 — **사용자 몫 25**(ECOS 키 8: 금리·CPI·PPI·스프레드 / KRX 승인 17: 수급·공매도·프로그램·파생),
    **에이전트 몫 30**(이벤트 클러스터 20 · 그래프 4 · SNS 3 · 기타 3). 자격증명 항목은 사용자에게
    '무엇을 어디서 발급·승인해 어디에 넣고, 몇 피처가 회수되는지'까지 붙여 체크리스트로 넘긴다.
- 그룹별 원인 분류(수집기 미실행 / writer 코드 부재 / 자격증명 무효 / 상류 사이트 개편 / 부분·경과 데이터)와
  입력 테이블↔피처 매핑, 되살리기 검증 프로토콜은 `references/dead-feature-revival.md`.
- 라벨·피처셋이 성능을 지배한다: 다음날 방향 라벨(up_rate≈0.47)에서 173피처 전량 모델은 0.51 수준이고,
  0.60+ 는 curated 소수 피처 + 얕은 트리 조합에서 나온다 → `references/ml-champion-training.md`.
  **단, 라벨 호라이즌을 늘리는 방향은 닫혔다(실측)**: 확장창 5폴드×3시드에서 h8 0.5068 / 시장상대 h8 0.5048
  vs h5 0.5406 (Δ−0.0338, h8 폴드가 전부 0.48~0.54 = 무작위). 단일분할에서 0.5961/0.5727 을 냈던 같은
  설정이 확장창 프로토콜에서 재현되지 않았다 → 프로토콜이 다른 숫자로 방향을 열지 말고, 같은 프로토콜에서
  다시 재기 전에 어떤 설정도 "유망"이라고 쓰지 않는다.
- 임베딩 모델(디바이스·CPU 처리량·교체 선행조건·로컬 LLM 전환): `references/embedding-cpu-and-gpu-readiness.md`.
- **"데이터를 채웠는데 AUC 가 안 오른다"는 질문은 측정 여부부터 확인한다.** ML 이 읽는 것은 집계 테이블(`stock_sentiment`)이지 원문 테이블(`news_analysis`)이 아니다 — 원문만 백필된 상태에서는 AUC 가 움직일 수 없고, 그때 올바른 보고는 "안 올랐다"가 아니라 **"아직 재학습으로 측정하지 않았다"**다. 단계 체인 진단 쿼리·집계기 함정·커버리지 상한은 `references/news-sentiment-feature-revival.md`.

## 5. 보고 형식

- 실험 결과표(설정 · 시드별 AUC · 평균±std · OOS) → 최고 모델 경로 → 게이트 판정 → 승격 여부·백업 경로 →
  재현 명령 → 되돌리기 명령 → 한계. 사용자는 이 형식을 기대한다.

## 6. 이동·복귀 재개 (노트북을 들고 다니는 환경)

- 리포에 `scripts/train_departure_prep.sh`(출발 전: 인플라이트 정지 + DB 보존 + 커밋·푸시) /
  `scripts/post_restart_check.sh`(복귀 후 7항목)가 있다. 복귀 요청을 받으면: 컨테이너 수(17) → `post_restart_check.sh`
  → 미커밋분 커밋·푸시 → 원장에서 죽은 사이클 확인 후 `--start <ID>` 로 재개하고 **로그가 실제로 자라는지** 확인.
- **`post_restart_check.sh` 의 크론 섹션은 `~/.hermes/cron/*.json` 존재만 본다** — 자율 루프가 죽어 있어도 통과한다.
  실제 스케줄·`next_run_at`·enabled 는 Hermes 크론 목록 도구로 따로 확인하고 그 결과를 보고에 쓴다.
- 구동기·컨테이너 로그 시각은 **UTC** 다(05:55 = 14:55 KST).
- 외부 종료(SIGKILL)로 죽은 사이클은 원장에 rc=137 로 남고 백로그가 pending 으로 돌아간다 → 체크포인트에서 이어서 시작하면 된다.
- 사람이 해야 하는 것(브리지 재기동·Creon 로그인)은 별도 스킬 소관이지만, 복귀 보고에는 **정확한 명령 + 마감 시각 +
  내가 검증할 방법**을 붙인다.
- 사용자가 이동·부재라 `clarify` 가 **타임아웃되면 권장안으로 진행**하고 되돌리는 정확한 명령(예: 크론 잡 제거)을
  보고에 함께 적는다 — 판단 하나 때문에 준비를 멈추지 않는다.
