# KRX OpenAPI (한국거래소 Data Marketplace)

한국 주식/지수 일별 데이터를 종목별 호출 없이 받는 공식 경로. **날짜 1개 = 그날 전 종목**이 한 응답으로
오기 때문에 종목별 시세 API(KIS 등) 대비 호출 수가 수십 배 적다 — 과거 이력 백필의 기본 선택이다.

## 1. 호출 형식

```
GET https://data-dbg.krx.co.kr/svc/apis/<경로>?basDd=YYYYMMDD
Header: AUTH_KEY: <인증키>      (토큰 교환·서명 없음)
```

- 호스트는 후보를 순서대로 찔러 **JSON 을 돌려주는 쪽**을 골라 상태파일에 캐시한다: `data-dbg.krx.co.kr` 는 정상 JSON 을 주고, `data.krx.co.kr/svc/apis/...` 는 같은 경로에 404(HTML) 를 줄 수 있다.
- 레거시 스크래핑 엔드포인트 `/comm/bldAttendant/getJsonData.cmd` 는 호출 금지 — 요청 제한 위반으로 IP 차단을 받았던 경로이고 지금도 403 이다. 공식 `/svc/apis` 만 쓴다.

## 2. 서비스 경로 (실측)

| 분류 | 경로 |
|---|---|
| 주식 | `sto/stk_bydd_trd` (유가증권), `sto/ksq_bydd_trd` (코스닥), `sto/knx_bydd_trd` (코넥스) |
| 주식 | `sto/stk_isu_base_info`, `sto/ksq_isu_base_info` (종목기본정보·상장주식수) |
| 지수 | `idx/kospi_dd_trd`, `idx/kosdaq_dd_trd`, `idx/krx_dd_trd`, `idx/drvprod_dd_trd`(파생지수) |
| 증권상품 | `etp/etf_bydd_trd` (ETF), `etp/etn_bydd_trd`, `etp/elw_bydd_trd` |
| 채권 | `bon/kts_bydd_trd`, `bon/bnd_bydd_trd`, `bon/smb_bydd_trd` |
| 파생 | `drv/fut_bydd_trd`(선물 外), `drv/eqsfu_stk_bydd_trd`, `drv/eqkfu_ksq_bydd_trd`, `drv/opt_bydd_trd`, `drv/eqsop_bydd_trd`, `drv/eqkop_bydd_trd` |
| 일반상품 | `gen/oil_bydd_trd`(석유), `gen/gold_bydd_trd`(금), `gen/ets_bydd_trd`(배출권) |
| ESG | `esg/esg_etp_info`, `esg/sri_bond_info`, `esg/esg_index_info` |

**접두사를 틀리면 승인과 무관하게 404** 다(실측 실패: `etf/`, `sec/`). `drv/`·`gen/` 는 실재하는 접두사다
— 2026-09-24 실측: `drv/fut_bydd_trd` 200, `gen/oil_bydd_trd` 200, 반면 `drv/eqsfu_stk_bydd_trd`·`drv/opt_bydd_trd`·
`gen/gold_bydd_trd`·`gen/ets_bydd_trd`·`idx/drvprod_dd_trd` 는 같은 키로 **401(서비스 미승인)** 이었다.
같은 접두사 안에서도 승인된 것/안 된 것이 섞이므로 "접두사가 틀렸다"로 뭉뚱그리지 말고 **엔드포인트별 200/401** 로 기록한다.

경로를 추측하지 않는다 — 서비스 31종의 `api_id`+`path`+`BO_ID` 전체 표를 공개 카탈로그에서 확인할 수 있다:
`https://raw.githubusercontent.com/awuzag/krx/main/docs/services.md` (서비스별 `apis/<분류>/<api_id>.md` 문서 링크 포함).

## 2a. 파생(선물) 응답 해석 — 2026-09-24 실측

`drv/fut_bydd_trd?basDd=YYYYMMDD` 한 콜이 그날 **전 파생상품**(지수선물·미니·섹터·국채·통화·금·변동성)을 준다.

| 필드 | 의미 |
|---|---|
| `PROD_NM` | 상품명(예: `코스피200 선물`) — 상품 단위 집계 키 |
| `MKT_NM` | **`정규` / `야간` 세션이 같은 `basDd` 에 별도 행으로 온다** — 세션을 고르지 않으면 거래량이 이중집계된다 |
| `ISU_NM` | 계약명(`코스피200 F 202612 (주간)`, 스프레드는 `... SP 2612-2703 ...`) |
| `TDD_CLSPRC` | 그 계약 종가, `CMPPREVDD_PRC` 전일대비(→ 등락률 계산), `ACC_TRDVOL` 거래량, `ACC_OPNINT_QTY` 미결제 |
| `SPOT_PRC` | **그 행의 현물지수**(코스피200 선물 행이면 `코스피200` 지수 = `idx/kospi_dd_trd` 의 `코스피 200`.`CLSPRC_IDX` 와 일치) → 베이시스를 지수 콜 없이 계산 가능 |

- "프론트월" 계약 = `정규` 행 중 종가가 있는 것들에서 **거래량 최대**로 고른다. 스프레드(`ISU_CD` 가 `D` 로 시작 / `ISU_NM` 에 ` SP `)는 계약이 아니므로 단독 계약이 하나라도 있으면 제외한다 — 안 그러면 통화·금리 선물의 대표 종가가 스프레드 값(0 근처)이 된다.
- 야간 세션은 백필에서 빼고 `정규` 만 적재하는 편이 안전하다(같은 날짜에 두 세션이 겹쳐 상수 왜곡이 생긴다).
- 파생 피처 리더 계약(이 레포 계열): `krx_derivatives.close_price + index_name`(index_name='KOSPI200' 은 하루 1행만 세팅) → `futures_premium`,
  `SUM(krx_derivatives.volume)` → `derivatives_volume`, `futures_options.basis`(= 선물 프론트월 종가 − 현물지수, 지수 포인트) → `basis`/`basis_change_5d`.
- **리더가 `trade_date = %s` 로 쓰여 있어도 as-of(`<=`)로 바꿔야 한다** — 휴장일·주말 날짜로 피처를 만들면 0 이 되어 "데이터 없음"으로 오진된다(시세 로딩도 `<= date` 규칙을 쓴다).
- 콜 예산: 날짜 1개 = 2콜(선물+지수). 98거래일(2026-05-04~09-23) = 196콜 ≈ 11분, 3.0s+지터.

## 2b. 카탈로그에 **없는** 것 — 수급·공매도·프로그램매매 (실측)

서비스 31종을 전수 확인한 결과 **투자자별 매매동향(수급)·공매도·프로그램매매 서비스는 없다**. 있으면
`sto/`·`idx/` 에 있어야 할 자리다. 그래서 "KRX OpenAPI 로 수급 받자"는 시도는 카탈로그 앞에서 끝난다.

- **수급(외국인/기관 순매수)·공매도·프로그램매매 → KIS 경로**가 정식 대체다(토큰 발급 + 종목별 호출,
  레포의 `kis_supply_backfill.py`·`kis_short_selling_backfill.py`·`kis_program_trading_collect.py`).
  KRX 쪽 스크래핑(pykrx)은 KRX 사이트 개편으로 **0행**이 되고 `warning` 만 남으므로 진단에서
  "OpenAPI 로 하면 된다"로 넘어가기 전에 **카탈로그에 있는지부터 확인**하라.
- 지수·파생은 OpenAPI 에 있다 → 컨테이너의 pykrx 기반 지수 수집기가 `KeyError '지수명'` 으로 죽어도
  `idx/kospi_dd_trd`·`drv/fut_bydd_trd` 러너로 대체할 수 있다.
- **러너가 있어도 크론에 없으면 정지한다**: 진행파일(`data/krx/*_progress_*.txt`) 최신 시각과
  `/etc/cron.d/` 항목을 대조하라. 진행파일이 며칠 전이면 아무도 안 돌린 것이다(수동 실행 의존).

## 3. 응답 3종으로 원인을 가른다

- 키 없음 → `{"respMsg":"Unauthorized Key"}` (401) — 자격증명 미설정
- 키 유효·서비스 미승인 → `{"respMsg":"Unauthorized API Call"}` (401) — **서비스 이용신청이 안 된 것**
- 경로 오류 → `{"respCode":"404","respMsg":"[svc/apis/<경로>] API referenced by the path does not exist"}`

헤더 이름/전달 방식을 바꿔 재시도하는 건 시간 낭비다(AUTH_KEY·쿼리·소문자·Authorization 모두 동일 응답이면 형식 문제가 아니다). 401 이 오면 헤더가 아니라 **계정의 승인 상태**를 본다.

## 4. 승인은 2단계다 (가장 자주 막히는 지점)

1. `https://openapi.krx.co.kr` 가입(개인은 본인인증/소셜) → 마이페이지 > **API 인증키 신청** → 승인(1일 내외, 이메일 통보)
2. 상단 **서비스 이용 > 주식(또는 지수)** → 원하는 API 페이지 하단의 **'API 이용신청'** 버튼 → 기간(12개월) + 신청목적 → 확인
3. 마이페이지 > **API 이용현황** 에 "승인대기"로 보여야 접수된 것이다. **비어 있으면 2번을 안 한 것** — 인증키 승인과 서비스 이용승인은 별개다.

- **키 재발급(갱신)을 권하지 않는다**: 승인은 인증키에 묶여 있어 재발급하면 이용신청·승인이 초기화될 수 있다. "Unauthorized API Call" 을 키 문제로 오진하고 갱신부터 제안하면 사용자가 며칠을 날린다.
- 신청서에 호출 IP/URL 칸이 있으면 호출 측의 현재 공인 IP 를 넣는다(장비 교체로 IP 가 바뀌면 무권한이 될 수 있다). 인증키 유효기간 1년, 양도 금지.

## 5. 응답 형태·해석

- 본문은 `{"OutBlock_1":[ ... ]}` 이고 **정상 응답에는 `respCode` 필드가 없다** — 성공은 `OutBlock_1` 존재로 판정한다(부재를 오류로 판정하면 첫 날짜에서 즉시 중단한다).
- 수치는 콤마 없는 문자열, 빈 문자열/`-` 가 섞인다 → 0/None 으로 정규화. 필수 키(`ISU_CD`, `TDD_CLSPRC`) 누락 행은 스킵.
- 휴장일은 행이 오되 가격이 빈값 → 휴장으로 판단해 휴장 파일에 기록하면 공실 점검과 공유된다.
- 일별매매정보는 **당일 데이터를 주지 않는다**(보통 D-2 반영) → 구간 종료일을 안전하게 D-1 로 둔다.
- 업서트는 `ON CONFLICT (stock_code, trade_date) DO UPDATE` — 다른 수집기가 먼저 넣은 값 위를 공식값으로 덮는다.

## 6. 호출 규율 (IP 차단 이력 계정)

과거 요청 제한 위반으로 IP 차단을 받은 적이 있으면 다음 기본값을 **env 로만** 낮추고 절대 조이지 않는다:

| 항목 | 기본값 |
|---|---|
| 호출 간격 | 3.0초 + 지터 0~0.5초 |
| 실행 간 최소 간격 | 60초(상태파일 공유 — 크론과 수동 실행이 겹쳐도 몰아치지 않음) |
| 실행당 호출 상한 | 600콜 |
| 재개 | 날짜별 진행파일(이미 받은 날짜는 재호출 안 함) |
| 차단 신호 | 401/403/429/5xx → **재시도 0회, 즉시 종료(exit 3)** |

예산 감각: 영업일 1년 ≈ 265일 × 시장 2콜 = 약 530콜 ≈ 30분. 같은 기간을 종목별로 받으면 2,600종목 × 3콜 ≈ 8,000콜(12시간)이다.

백필 러너 설계 (같은 함정에 두 번 데인 규칙):
- **유니버스는 종목 마스터(`stocks`)에서 가져온다.** 이미 적재된 시세(`market_data`)를 스코프로 삼는 러너는 **빈 DB·신규 배포에서 대상 0건으로 조용히 끝난다** — '대상 0' 로그를 보면 스코프 줄을 의심하고 마스터 기반 폴백을 넣는다.
- 진행률은 **날짜별 진행파일**로 남기고, 실행당 상한에서 멈춘 지점을 다음 실행이 이어받게 한다.
- **진행파일이 곷 수집 여부를 결정한다 — "0콜 / 0행 완료" 로그를 실패로 오진하지 않는다.** 같은 구간을 다시 돌리면 이미 기록된 날짜가 전부 스킵되어 `완료: 0영업일 적재, 휴장 0일, 0행 upsert, 호출 0회` 로 끝난다(크론이 매일 구간을 밀어 최근 N일을 재검증하는 경우도 같다 — 중복 방지가 작동한 것이다).
  반대로 **같은 구간을 실제로 다시 받아야 할 때**(다른 소스가 넣은 값을 공식값으로 재수집)는 진행파일 이름이 달라지도록 구간을 바꾸는 게 가장 안전하고, 필요하면 진행파일을 무시하는 명시적 플래그를 쓴다 — 파일을 그냥 지우면 재개 이력도 함께 날아간다.
- 다른 수집기가 먼저 넣어둔 값(예: yfinance 일괄 적재) 위를 이 러너가 공식값으로 덮는다 → 백필 도중 행 수가 늘거나 값이 바뀌는 것은 정상이며 고장으로 오진하지 않는다.

## 7. 검증

- 서비스 승인/경로를 한 번에 확인: `KRX_API_KEY=<키> bash scripts/krx_service_probe.sh [YYYYMMDD]` (경로별 200/401/404 + 본문 앞부분, 연속 호출에도 1초 간격)
- 백필 후 커버리지: 영업일별 적재 종목 수가 정상치(2,600+)에 못 미치는 날짜를 찾는다.

## 8. 보고 방식 (사용자 선호)

원인 진단형 보고를 쓴다: **①실측 증거(응답 코드·본문 그대로) → ②원인 한 줄 → ③사용자가 직접 해야 할 정확한 클릭 경로/URL 또는 명령 → ④번호 옵션 + 추천**. 승인처럼 상대방만 할 수 있는 단계는 "제가 대신 못 한다"를 먼저 밝히고 그 단계만 요청한다. 키를 다시 받아도 안 풀리는 문제(권한)는 재시도 대신 진단으로 전환한다.
