# 실주문 전략의 분봉 재생 측정 (일봉 애매 구간을 없애는 절차)

좁은 손절/익절(1~3%) 전략을 일봉으로 검증하면 **판정이 가정에 달린다**. 일봉에는 장중 순서가 없어
같은 날 손절선과 익절선을 둘 다 터치하는 비율이 압도적이고(자본 제약 시뮬 실측: 애매 95.9%),
worst −0.74%/건 ~ best +0.71%/건으로 갈려 어떤 결론도 만들 수 없다. 그래서 **분 단위 경로**를 확보한다.

## 1. 데이터 소스 (실측으로 확인한 제약)

| 소스 | 범위 | 필드 | 함정 |
|---|---|---|---|
| KIS `inquire-time-itemchartprice` (수집기 `services/kis-collector`) | **당일만** | OHLCV | 페이지당 **30행 고정**(`fid_cnt=100` 요청해도 30) |
| Naver `api.finance.naver.com/siseJson.naver?symbol=..&requestType=1&startTime=YYYYMMDD&endTime=..&timeframe=minute` | 과거 **~6거래일/요청**, 5일 창으로 잘라 호출 | **종가·누적거래량만** (OHLC null) | `curl --noproxy '*'` 필요(프록시 환경에서 502/타임아웃) |

- **KIS 수집기 페이지 종료 조건을 `len(page_bars) < fid_cnt` 로 쓰지 마라.** 서버가 30행만 주면 그 조건이
  항상 참이라 **1페이지만 받고 끝나고**, 산출물은 하루 30행(마감 15:01~15:30)만 쌓인다.
  종료는 ① `oldest == 장 시작` ② 새 행 0 ③ `max_pages` 로 판정하고, 1페이지 결과가 요청 크기보다 작다는
  사실만으로 중단하지 않는다.
- 과거 분봉은 KIS로 **복구 불가**(당일만 제공) → Naver 백필로 채운다. `--sleep`(0.4초)로 호출을 제한하고
  5거래일 창으로 나눈다. 295종목·6일이면 약 15분·52만행 규모.

## 2. 저장 계약

- 새 테이블에 **있는 값만** 저장한다: `minute_close_bars(stock_code, trade_date, time, close_price, cum_volume, source)`,
  `PRIMARY KEY (stock_code, trade_date, time)`, 정규장(09:00~15:30)만, UPSERT(재실행 시 신규 0행).
- OHLC 가 없는 소스로 `open/high/low` 를 종가로 채우지 마라 — 그 순간 '고가 터치' 판정이 조용히 틀어진다.
  기존 `minute_bars`(다른 목적의 수집기 산출물)를 덮어쓰지 말고 **별도 테이블**을 둔다.

## 3. 재생 규칙 (가정을 코드에 박는다)

1. 진입은 신호일 t 의 **다음 거래일 시가**, 수량·비용·한도는 자본 시뮬레이터 로직을 **import 해서 재사용**한다(복붙 금지).
2. 청산은 그날 09:00 분봉 종가부터 순차로: 임계(진입가×(1±pct))를 **처음 넘은 분의 종가**에서 체결.
3. 같은 분에 양방향이면 **손절 우선**(보수)으로 계산하고 그 건수를 따로 센다.
4. 미도달이면 당일 마지막 정규장 종가로 청산.
5. 분봉이 없는 (종목,일)은 **일봉으로 대체하지 말고** `skipped_no_minute` 로 세고 **커버리지**(체결/(체결+skip))를
   함께 보고한다. 커버리지가 낮으면 낮다고 쓰고 판정 근거로 쓰지 않는다.

## 4. 판정에서 실제로 드러난 것 (방향 기준)

- **1% 손절은 −1%에 체결되지 않는다**: 1분 종가가 손절선을 관통해 평균 손실이 **2.2%** 로 커진다 →
  일봉 worst 가정조차 낙관적이다. 좁은 라인의 기대값은 분봉으로만 정직해진다.
- 같은 신호·같은 자본에서 규칙별 R 이 크게 갈린다(고정 1%/3% R≈1.7 vs ATR 트레일 R≈4.0) → **손익비 축이 먼저**이고
  승률은 그 다음이다. 승률이 같아도(16.7%) 기대값은 −1.21% vs −0.37%.
- 표본은 자본 제약이 결정한다: 신호 1.4만 건 중 실제 체결 가능은 **수백 건**(나머지는 슬롯·가격대 탈락) →
  "수백 번 반복" 판정에는 세션을 며칠~몇 주 쌓아야 하고, 하루 표본으로 결론을 내지 않는다.

## 5. 자본 제약 시뮬레이터 (같은 표에서 봐야 하는 것)

- 정수 수량(`floor(예산/가격)`), 종목당 상한(자본/3), 동시 보유·일일 건수, 가격대를 넣고
  **탈락 사유를 따로 센다**(`skipped_capital`·`skipped_price_band`·`skipped_slots`). 탈락을 세지 않으면
  "신호 1.4만 건"이 실제 체결 수백 건이라는 사실이 사라진다.
- **MaxDD 는 자본곡선으로 낸다.** 거래 수천 건을 전액 재투입 복리(∏(1+r))로 이으면 5,873% 같은 값이 나온다 —
  지표가 아니라 버그다. 측정 불가면 `null` + 사유를 쓰고 자본 시뮬레이터를 정본으로 적는다.
