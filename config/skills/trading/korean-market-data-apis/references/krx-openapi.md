## 4. KRX OpenAPI (진단 — 레포에 따라 미사용일 수 있음)

- 호출 형태: `https://data-dbg.krx.co.kr/svc/apis/<서비스>/<api>?basDd=YYYYMMDD`, 헤더 `AUTH_KEY: <key>` → JSON `OutBlock_1`. 토큰 교환/서명 없음.
- 서비스별 경로 예: `sto/stk_bydd_trd`(유가증권 일별매매), `sto/ksq_bydd_trd`(코스닥), `idx/kospi_dd_trd`(지수).
- 키가 승인되지 않은 상태의 전형적 응답이 바로 §1의 표 첫 줄(401 JSON)이다 — **경로가 맞다는 증거이므로 경로를 바꿔가며 헤매지 말고 콘솔 승인을 확인**한다.
  - 남은 단계는 4단계 중 3단계다: openapi.krx.co.kr 로그인 → 마이페이지 API 인증키 신청/발급내역(`/contents/OPP/MYPG/mypage/OPPMYPG001.cmd`)에서 키·유효기간(1년) 확인 → 서비스 목록(`/contents/OPP/INFO/service/OPPINFO004.cmd`, 주식 카테고리 `/contents/OPP/USES/service/OPPUSES002_S1.cmd`)에서 **API 활용신청** → 관리자 승인(보통 1일). 인증키 발급만으로는 호출되지 않는다 — 인증키는 “신원”, 활용신청은 “서비스별 권한”이다.
  - 신청할 서비스: 유가증권 일별매매정보(`sto/stk_bydd_trd`), 코스닥 일별매매정보(`sto/ksq_bydd_trd`), 선택적으로 종목기본정보(유니버스/상장주식수 보강)·지수 일별시세(시장 레짐 피처).
  - 승인 확인은 1콜 프로브로 한다(하루치 1마켓만 호출) — `respCode 200`과 종목 행이 오면 승인 완료, `Unauthorized API Call` 그대로면 대기 중이다. 헤더/호스트 변형을 손으로 시도하지 말고 이 스킬의 `scripts/krx_probe.py`를 쓴다(JSON 응답이 오는 순간 멈춤).
- **차단 이력이 있는 소스는 보수적 호출 정책을 러너의 기본값으로 박는다**: 호출 간 지연+지터, 실행 간 최소 간격(공유 상태파일에 기록해 크론·수동 실행이 겹쳐도 몰아치지 않게), 실행당 호출 상한, 차단 신호에서 재시도 없이 즉시 종료, 날짜/구간별 진행파일로 재개. 파라미터는 전부 env로 빼서 상향 조정에 코드 수정이 필요 없게 한다.
- **"가격이 빈 행 = 휴장" 판정을 최근 날짜에 적용하면 데이터를 영구히 잃는다.** 일별매매정보는 D-1(실제로는 D-2)까지 반영되므로, 아직 공표 전인 날짜를 조회하면 전 종목 가격이 빈값으로 온다. 이걸 휴장으로 파일에 기록하면 그 날짜는 이후 모든 러너가 건너뛴다(휴장 캐시가 스킵 근거가 된다). 러너는 ① 종료일 기본값을 `today`(−1)가 아니라 "DB 최신일 다음날" 기준으로 잡고, ② 최근 2일 이내 날짜는 휴장 확정을 보류해 다음 실행에서 재확인한다. 휴장일은 파일에 기록하기 전에 그 날짜가 이미 시세를 가진 적이 없는지도 확인한다.
- **무거래·거래정지 종목도 행으로 온다** — 시가·고가·저가가 0, 거래량 0, 종가만 기준가로 채워진 행이 섞인다(1년 패널에서 579종목·28,282행, 최근 일평균 약 113종목). 종가만 보고 넘기면 수익률·MA 위치·변동성 피처가 0 기준으로 계산되므로 소비 측(피처 빌더)에서 `open=high=low=0` 행을 제거하거나 플래그를 세운다.
- pykrx는 이 OpenAPI가 아니라 `data.krx.co.kr/comm/bldAttendant/getJsonData.cmd`(레거시 JSON)를 쓴다. 그 경로는 WAF로 IP 차단된 이력이 있고 "KRX 수집이 죽었다"의 원인이 보통 이것이지만, **차단 여부는 IP대역·시점에 따라 다르다** — 같은 호스트의 보조 수집기가 pykrx로 정상 수집 중인 경우도 있다(실측). "차단됐다"를 전제로 설계하지 말고 1콜 프로브로 현재 상태를 확인한 뒤 경로를 고정한다. 같은 데이터를 주는 경로가 둘 이상이면 **호출 수가 적은 쪽을 기본으로, 실패 시 다른 쪽으로 폴백**한다.
- 경제성: 일별매매정보는 **시장 1콜로 그날 전 종목**이 온다(KOSPI `sto/stk_bydd_trd` + KOSDAQ `sto/ksq_bydd_trd`) → **날짜당 2콜, 1년 약 500콜**(실측 247거래일 = 494콜, 3.0s+지터로 57분). 같은 기간을 KIS 종목당 1콜로 받으면 2,700콜 이상이므로, 승인돼 있다면 과거 일봉 백필은 이 경로를 우선한다.
- **승인 카탈로그로 "이 계정에 무엇이 열려 있나"를 먼저 확정하라.** 실제로는 몇 묶음이다: 지수(시리즈·파생상품지수·ESG) ·
  일별매매정보(유가/코스닥/코넥스/신주인수권 2종) · 종목기본정보 · ETF/ETN/ELW · 채권 3시장 ·
  **파생(선물·주식선물 유가/코스닥·옵션·주식옵션)** · 원자재(석유/금/배출권) · ESG 증권상품.
  **투자자별 거래실적(수급)·공매도·프로그램매매는 이 카탈로그에 없다** → 그 피처군을 KRX 로 풀려고 서비스 신청을 기다리거나
  경로를 뒤지지 말고, 즉시 KIS·다른 소스로 피벗한다(§1 표의 401 진단과 함께 판단).
- **없는 엔드포인트는 404 JSON 으로 바로 드러난다**: `{"respMsg":"[svc/apis/...] API referenced by the path does not exist.","respCode":"404"}`.
  경로 이름을 추측해 여러 개를 던져보지 말고, 살아있는 경로 1콜(`sto/stk_bydd_trd?basDd=YYYYMMDD`)로 키·승인을 먼저
  확인한 뒤 카탈로그에 있는 이름만 시도한다(프로브는 1~2콜로 제한).
