# 한국 시장 데이터 API (KIS · KRX · Naver)

한국 주식 데이터를 수집하는 모든 작업(유니버스 시딩, 일봉/분봉 백필, 감정분석용 LLM)의
자격증명 위치·호출 모양·호출 경제성·오류 진단. 프로젝트별 절차는 각 레포 문서가 갖고,
여기에는 재사용되는 API 지식만 둔다.

## 0. 자격증명 반영·검증 (모든 소스 공통)

1. `.env`(또는 동등한 런타임 env)에 기록한다. 값은 파일에만 — 임시 python 스크립트로 쓰고 즉시 삭제해 transcript에 값이 남지 않게 한다. `chmod 600`.
2. **컨테이너는 `docker compose up -d`로 재생성해야 `env_file`이 반영된다**(설정이 바뀐 서비스만 Recreate). 호스트에서 도는 크론·스크립트는 `.env`를 `source`하므로 재기동 불필요.
3. 검증은 **컨테이너 안에서 실제 호출**로 한다 — 호스트 curl이 200이라도 컨테이너에 env가 들어갔다는 증거는 아니다.
4. 새 키를 받으면 "그 키로 실제 **되는 경로가 무엇인지**"를 먼저 확인한다: 레포에서 그 키를 쓰는 코드를 `grep` → 없으면 실호출로 엔드포인트를 확인. 안 되는 키를 "설정했습니다"로 끝내면 사용자는 수집이 도는 줄 안다 — 되는 것과 안 되는 것을 나눠서 보고한다.
5. 러너는 키 미설정 시 **fail-fast**(메시지 + `exit 2`)하게 만든다. 조용히 0건 수집하면 크론 로그가 성공처럼 보인다.
6. **키의 "존재"와 "유효"는 다르다 — 실호출 프로브로 성공을 확인한 뒤에만 .env에 반영한다.**
   디스패처가 `[ -n "$APP_KEY" ]` 같은 **존재 검사**로 수집 소스를 고르게 되어 있으면, 인증 실패하는 키를 넣는
   순간 잘 돌던 폴백 경로(KRX 등)가 선택 해제되어 야간 수집이 통째로 죽는다. 순서를 지킨다:
   (a) 키 전용 1콜 프로브(예: KIS 토큰 발급, KRX 하루치 1마켓) → (b) 성공하면 .env 반영, (c) 실패하면
   .env에서 **빼고** 보류 파일(예: `~/<source>_keys.pending.env`, 0600)로 옮긴 뒤 "보류 중, 폴백 경로 유지"를 보고.
   구조적 해법은 디스패처에 "프로브 성공 시에만 A, 실패 시 B" 분기를 넣는 것 — 만료·오타 키가 수집을 멈추지 못하게 한다.
7. **붙여넣은 자격증명은 쓰기 전에 자체 검증한다.**
   - base64 시크릿(앱시크릿·인증키) 길이는 **4의 배수**여야 한다. 179처럼 나머지가 3이면 잘림이 확정이므로 재복사를 요청한다.
   - 파일에 쓴 값이 사용자가 준 문자열과 **정확히 같은지** 대조한다(앞뒤 공백·비표준 문자·개행 포함 여부). 값 비교는 hash 접두어로만 출력해 transcript에 원문을 남기지 않는다.
   - 검증 커맨드에 시크릿 리터럴을 쓰지 않는다 — `.env`를 `source`한 뒤 `"$APP_SECRET"`을 curl 인자로 넘긴다.

## 1. 잘못된 응답 코드를 상태로 읽기 (핵심 규칙)

| 응답 | 진단 | 행동 |
|---|---|---|
| `401` + JSON `{"respMsg":"Unauthorized API Call"}` | 엔드포인트는 맞고 **키가 그 서비스에 승인되지 않음** | 콘솔에서 서비스 신청/승인 확인. 경로 변형을 더 시도해도 결과 동일 |
| `404` | 호스트/경로가 다름 | 호스트를 바꾼다 (예: 운영 호스트엔 `/svc/apis` 경로 자체가 없을 수 있음) |
| `403` + HTML | WAF/IP 차단 | 재시도 무의미. 다른 소스(KIS 등)로 피벗 |
| `200` + 기대한 필드 없음 / **0건** | 파서는 돌았지만 내용이 없음 — **성공으로 취급하지 않는다** | 스크래핑 대상 사이트가 개편(SPA 전환)된 경우가 대표적 |

- **리다이렉트된 HTML을 파싱하면 0건이 조용히 나온다.** DOM 선택자가 사라진 게 아니라 응답이 다른 페이지다 — `follow_redirects=True`면 상태코드는 200으로 보인다. "수집 0건"을 반드시 실패로 보고 원인을 찾는다.
- OpenAI 호환 LLM 엔드포인트의 `/v1/models` 목록은 **호출 가능한 모델의 전체 목록이 아니다**(목록에 `deepseek-flash`/`deepseek-v4-pro`만 있어도 `deepseek-chat`이 completion에서 200으로 답한다). 목록을 보고 모델명을 "고치지" 말고 실제 completion으로 검증한다.

- 상세: `references/kis-openapi.md` — 2. KIS OpenAPI (한국투자증권 — 일봉/분봉 수집의 주 소스)

## 3. Naver 금융 (유니버스 시딩 — 키 불필요)

- `finance.naver.com/sise/sise_market_sum` 은 SPA로 전환되어 `page=` 링크가 없다 → 기존 HTML 파서가 **0종목**을 반환한다(위 §1).
- 대체(실측 동작): `https://m.stock.naver.com/api/stocks/marketValue/{KOSPI|KOSDAQ}?page=N&pageSize=100`
  - JSON `stocks[]`에 `itemCode`, `stockName`, `stockEndType`, `marketValue`; `totalCount`로 종료 판단; 페이지는 100건씩(마지막 다음 페이지는 빈 배열)
  - **ETF/ETN 제외는 `stockEndType != 'stock'`** — KOSPI는 이 필터로 2,484행 → 945종목 (시총 상위에 ETF가 섞여 있다). KOSDAQ은 1,820 모두 주식. 합계 약 2,678종목이 실제 주식 유니버스.
- 6자리(`\d{6}`) 코드만 저장 — 우선주/신형 코드가 섞이면 유니버스가 오염된다.

### 3a. 지수 일봉(KOSPI/KOSDAQ) — 키 없이 `siseJson`, 레짐 판정의 전제

레짐 분리(`risk_off` 게이트, 하락장 조건부 측정)를 하려면 **지수 일봉**이 필요한데 종목 시세 테이블에는
지수가 없다. 이때 종목 일별 수익률 중앙값(breadth)을 프록시로 쓰면 **하락일을 과다 분류**해 표본 구성이
달라진다(실측: 같은 기간 하락 표본 655 vs 303) → 프록시는 임시방편이고, 지수를 한 번 받아 두면 된다.

- `https://api.finance.naver.com/siseJson.naver?symbol=KOSPI&requestType=1&startTime=YYYYMMDD&endTime=YYYYMMDD&timeframe=day`
  (`symbol=KOSDAQ` 도 동일). **키·토큰 불필요**, 1콜로 수년치가 온다(실측: 459거래일 × 2지수 = 2콜).
- 응답은 **JSON 이 아니라 작은따옴표 파이썬 리스트 리터럴**이다 — `json.loads` 는 죽는다. `ast.literal_eval`
  로 파싱하고 **첫 행은 헤더**(`['날짜','시가','고가','저가','종가','거래량','외국인소진율']`)이므로 버린다.
  날짜는 `YYYYMMDD` 문자열, 값은 문자열/None 혼재 → 숫자 변환 시 None 스킵.
- 저장은 신규 테이블 `index_daily(index_code, trade_date, open, high, low, close, volume)` + PK 멱등 upsert.
  재실행 시 행수 불변을 확인한다(실측 918행 불변).
- 이것으로 **레짐을 실측 지수로 판정**한다: `close < MA20` 또는 `5일 수익률 <= -3%` → `risk_off`.
  지수 결측은 0/추정으로 메우지 말고 `unknown + 사유`로 남긴다(그 상태의 게이트는 fail-open + 경고 1줄).
- 주의: 지수 일봉은 **종가 기준**이라 장중 레짐 판정에는 쓰지 않는다. 장중 판정이 필요하면 같은 심볼의
  분봉/현재가 경로를 따로 확인하고, 일봉 기준 게이트는 "전일 종가 기준"임을 리포트에 명시한다.

### 3b. 업종(sector) 채우기 — Naver 업종분류가 '종목당 1콜'을 대체한다

`sector` 가 비어 있는 종목이 65%(실측 2,809/4,353)일 때 KIS 로 채우면 `FHKST01010100` output 의
`bstp_kor_isnm`(업종명, 실측 `전기·전자`)을 쓰는 종목당 1콜 = 2,809콜 ≈ 2.7시간이다. Naver 는 **~103콜/1분**으로 끝난다:

- 업종 목록: `GET https://m.stock.naver.com/api/stocks/industry?page=N&pageSize=100` → `groups[{no,name,totalCount}]`(totalCount 로 종료)
- 업종별 종목: `GET .../api/stocks/industry/<no>?page=N&pageSize=100` → `groupInfo.name`(**업종명**) + `stocks[].itemCode`(페이지당 100)
- 6자리 코드만 채택하고 **빈 `sector` 만 UPDATE** 한다 — 일부 스택은 `sector` 컬럼에 상품구분(`ETF`/`ETN`)을 넣어 두므로
  덮어쓰기는 별도 플래그로 분리한다. 실측 결과 결측 2,809 → 135(KONEX·신규·업종 미분류).
- 호출은 기존 `net_guard('naver')` 키를 경유시키고, 주 1회 크론으로 신규상장분만 채운다(멱등).

**업종명을 안 주는 경로(추측 금지)**: KRX `sto/stk_isu_base_info` 의 `SECT_TP_NM` 은 KOSDAQ **소속부**
(`우량기업부`)이고 KOSPI 는 빈 값이다 — 종목기본정보로 업종을 채우려 하지 마라. Naver
`.../stock/<code>/basic`·`/integration` 은 `industryCode`(숫자)만 주고, `/api/industry/<no>` 는 404 다.
이름은 업종 목록/업종별 응답의 `groupInfo.name` 으로만 얻는다.

### 3c. 상권·자영업 매출(대안 데이터) — 어디가 열려 있고, 모델에 쓸 수 있나

- 열린 경로(실측): ① 서울 열린데이터광장 「서울시 상권분석서비스(추정매출-상권)」 OA-15572 — **분기**,
  자치구·행정동·상권×업종 추정매출(신한카드 결제 + 보정비율), 무료 키 ② 공공데이터포털
  「서울시 상권분석서비스(추정매출_자치구)」·「경기도 발달/골목상권 추정매출」(JSON+XML, KSIC 10차, 자동승인)
  ③ 신한카드 DataBada(업종별 매출·신규/해지 매장)는 **B2B 심사·계약 대상**이라 무료 오픈API 로 가정하지 마라.
- 소상공인 상권정보(상가업소 200만건)에는 **매출이 없다**(업소·업종 정보만) — 매출 원천으로 쓰지 않는다.
- **모델 적합성 판정을 수집보다 먼저 한다**: 지역×업종×분기 매출은 시장/섹터 레벨이라 종목에 붙이면 같은
  업종 종목이 동일값이 되어 횡단면 변별력이 0 이다(§11 의 시장레벨 판정과 같은 이유, 계약상 횡단면 피처 부적격).
  종목 차별화는 사업보고서 세그먼트 매출·점포수와 결합해야 성립하고 그건 별도 프로젝트다 → 기본 용도는
  **소비재 레짐/섹터 게이트·대시보드**이고, 갱신이 분기라 일 단위 매매 신호에는 못 쓴다.
- 키가 없으면 그건 사람 단계다(data.go.kr·서울 열린데이터광장 키는 무료·자동승인). 키를 받으면 크론을 걸기 전에
  **1콜 프로브**로 응답 필드(업종코드·매출금액·기준분기)를 확인하고, 종목 피처가 아니라 게이트/리포트 소비처를
  먼저 정한다 — 쓸 곳이 없는 수집은 커버리지만 늘린다.

### 3d. 장중 실시간 시세·지수 — "오늘 X 테마 왜 올랐나" 확인용 (키 불필요)

테마·섹터 급등 원인을 물으면 기억·뉴스 요약만으로 답하지 말고 **① 실제 등락 ② 지수 동시 등락 ③ 기사 원문**을 붙인다.

- 종목: `GET https://polling.finance.naver.com/api/realtime/domestic/stock/<code>,<code>,...`(콤마로 다종목 한 콜)
  → `{time, datas:[...]}` 이고 항목은 `itemCode`·`stockName`·`closePrice`·`compareToPreviousClosePrice`·
  `fluctuationsRatio`(**문자열 % — 정렬·비교 전 `float()` 필수**)·`accumulatedTradingValue`·`marketStatus`(`OPEN`)·`localTradedAt`.
- 지수: 같은 호스트 `/api/realtime/domestic/index/KOSPI,KOSDAQ` → `datas[]` 의 현재값·등락률.
- **`m.stock.naver.com/api/stock/<code>/integration` 은 현재가·등락률 필드를 주지 않는다**(키 구조가 다름) — 현재가 용도로는 위 폴링 경로를 쓴다.
  `/basic` 도 필드를 확인한 뒤에만 쓴다.
- **테마 판정은 대형주와 초소형 테마주를 나눠 본다.** 실측: 지수 −5.5% 인 날 한 테마에서 상한가(+30%)·+24%·+20% 소형주가 나온 반면
  대표 대형주 2개는 −3% 였다 — breadth 없이 "테마가 올랐다"고 쓰면 오보다. 오전 10시 +4~5% 가 11시 반 +0.2/−0.5% 로 밀리는 일도 흔하므로
  **조회 시각을 반드시 적는다**.
- 원인은 ① 개별 재료(수주·공급계약·목표주가 상향) ② 수급 순환(다른 업종 투매 → 규제 리스크 낮은 테마로 이동)
  ③ 이벤트 기대(전시회·신제품) 로 나누고, 각각에 매체·핵심 문장 인용을 붙인다. 마지막에 "우리 후보/규칙에 걸렸는지"(피드 종목 대조,
  상한가·급등 필터 여부)를 한 줄로 붙이면 보고가 행동으로 이어진다.

## 12. ECOS (한국은행 경제통계) — 금리·물가·스프레드

매크로 피처의 원천. 키는 `ECOS_API_KEY` 하나이고, **키가 유효한데도 전부 0 이 나오는 실패 모드가 4가지** 있다(전부 URL·코드 문제이지 키 문제가 아니다).

- URL 고정 형태: `https://ecos.bok.or.kr/api/StatisticSearch/{KEY}/json/kr/{start}/{end}/{STAT_CODE}/{CYCLE}/{시작}/{끝}/{ITEM}`.
  **`StatisticSearch` 세그먼트를 빠뜨리면 게이트웨이가 HTTP 404(빈 본문)를 돌려주고, 코드는 그것을 "키 무효"로 오인한다** —
  키 재발급을 요청하기 전에 URL 조립부터 본다.
- **검증된 통계코드**(실응답 기준, 추측 금지): 기준금리 `722Y001`/D/`0101000` · 국고채3년 `817Y002`/D/`010200000` ·
  회사채3년 `817Y002`/D/`010300000` · CPI `901Y009`/M/`0` · PPI `404Y014`/M/`*AA`.
  국고채·회사채는 **같은 표(시장금리 일별)의 다른 ITEM** 이다. 없는 조합은 HTTP **200** + `INFO-200 해당하는 데이터가 없습니다` 로
  조용히 실패한다(§1 표의 "200 + 0건" 줄) — 상태코드만 보면 성공으로 오독한다.
- **요청 1회 = 최대 1,000행**이고 초과분은 잘린다 → 일별 시리즈는 **연 단위로 나눠 호출·병합**한다.
  그러지 않으면 응답이 과거에서 끊겨 가장 중요한 최신 값이 사라진다(3년 일별 ≈ 1,000영업일).
- **YoY 피처에 지수 레벨을 넣지 마라.** `cpi_yoy`/`ppi_yoy` 같은 이름의 피처에 지수(예: `120.05`)를 넣으면
  값이 비정상(non-stationary) 시계열이라 모델에는 시간 추세로만 작동한다 → `(현재/12개월 전 − 1)×100`.
  스프레드도 하드코딩 상수(3.5 등)를 기준선으로 쓰지 말고 실제 정책금리 기준으로 계산한다.
- 적재는 `(지표명, 날짜)` 유니크에 멱등 upsert 로 하고, **반드시 두 날짜 이상에서 피처값이 달라지는지** 확인한다
  (상수면 as-of 배선이 끊긴 것이지 데이터가 없는 게 아니다). FRED 계열(USD/KRW·JPY/KRW·CNY/KRW·WTI)은 키 없이 같은 러너로 채워진다.

## 8. KIS 엔드포인트 전수 프로브 ("무엇을 수집할 수 있나" 질문)

"이번에 KIS에 상품을 추가했다는데 수집 가능한가" 류의 요청은 **엔드포인트 카탈로그를 1콜씩 돌려** 확인한다(추측·문서 인용 금지).
프로브 스크립트: `scripts/kis_probe_all.py`(레포 `services/kis-collector` 의 클라이언트를 재사용, 호출 간 1.2s), 결과 카탈로그: `references/kis-endpoint-catalog.md`.

- **국내주식 엔드포인트는 ETF/ETN에도 그대로 통한다** — 별도 상품이 아니다. ETF가 안 돌고 있으면 대개 유니버스(`stocks`)에 없기 때문이다.
- **원유(유가) 노출은 해외선물이 아니라 해외주식 경로로 먼저 확인한다.** 해외선물 시세 TR 변형은 실측에서 전부 `EGW-UNKNOWN` 이었다(별도 신청 필요 가능성) — 반면 해외주식 현재가/일봉은 USO 같은 원유 ETF 심볼로 정상 응답한다. 어느 쪽인지 1콜로 가린 뒤 보고한다(미신청으로 단정하지 말고 "이 경로는 되고 저 경로는 안 된다"로 보고 + 신청 필요 여부 확인).
- 오류를 **세 갈래로 구분해 보고**한다: `OPSQ2001` = 필드명 오류(권한 문제 아님, 파라미터 교정 대상) / `EGW-UNKNOWN`(응답에 코드 필드가 없어 클라이언트가 붙인 값) = 경로·TR_ID 불일치 또는 미신청 / 권한 거부 메시지 = 콘솔 신청 필요.
- **경로 하나만 보고 "지원 안 함"으로 결론내지 말 것.** 거래량 순위는 `/uapi/domestic-stock/v1/quotations/volume-rank` 가 맞고 `/ranking/volume` 은 실패한다 — 같은 API의 구·신 경로 차이다. 문서·기억의 경로가 실패하면 변형 2~3개를 1콜씩 돌려 확정한다.

## 7. 종목·점수를 다른 시스템에 넘길 때 (피드 발행)

수집·학습으로 뽑은 종목을 매매 시스템(브로커 자동화 등)에 넘기는 단계는 별도 계약으로 관리한다. 소비 시스템의 계약 문서(필드·필수값·신선도·전략별 청산 규칙)가 있으면 **그것이 단일 진실**이다 — 형식을 만들거나 바꾸기 전에 읽는다. 게이트를 벗어난 후보는 소비 측이 조용히 버리고, 그 사실은 발행 로그에 나타나지 않는다.

- **발행물은 tmp에 쓰고 `os.replace`로 원자적 교체**한다 — 소비자가 폴링 중이면 반쪽 문서를 읽고 전 후보를 버릴 수 있다.
- **소스 산출물의 나이를 발행기에서 막는다.** 계약이 보는 "발행 시각"만 갱신하면 몇 주 전 스크리너 결과도 신선해 보인다 → 오래된 전략은 빈 리스트로 발행한다(기본 3일).
- **점수 분포를 발행 로그에 남긴다**(min/median/max/spread). spread<5면 문턱·상위 N 선별이 무의미해지고, 동일값이 수십 건인 경우(모델 배치 미연결·raw 폴백)는 아예 무작위 선별이다 — 그 전략은 실거래에 쓰지 않는다.
- **필수값은 발행 전에 채운다**: 가격 누락은 시세 테이블 최근 종가로 보정하고(0/누락이면 소비 게이트가 차단), 코드는 6자리 숫자만 통과시키고, 점수 없는 항목은 버린 뒤 점수 내림차순으로 정렬한다.
- **소비자 코드로 검증한다**: 소비 시스템의 파서를 그대로 불러 발행물을 파싱해 건수·가격 누락·점수 분포를 확인하는 점검 도구를 둔다(매매 엔진/브로커 로그인이 없어도 수행 가능).
- 발행 시각·데이터 기준일·전략별 건수를 돌려주는 `/health` 같은 장을 같이 띄워 두면 감사와 장애 판단이 빨라진다.
- **외부 랭킹(상승률·거래량 순위)을 점수 스크리너와 **교집합으로 결합하지 마라 — "압축"이 아니라 "대체"가 된다.**
  실측: 상승률 2~12% 상위 60코드와 칼만·모델 스크리너 상위 20건의 **교집합 0건**, 교집합 유니버스의 최고점 55.1
  vs 전체 65.5. 스크리너 상위는 수일 추세·모델 확률로 뽑혀 당일 등락률과 무관하기 때문이다. 대신
  ① 랭킹 상단(추격 구간)은 **배제 필터** ② 관심 밴드는 **정렬 전용 가점**(공개 `score` 값은 그대로) 으로 쓴다 —
  발행 점수 스케일을 바꾸면 소비자 문턱의 의미가 조용히 달라진다. 교집합을 쓰겠다면 교집합 건수·상위 점수를
  먼저 실측해 보고하고 판단을 받는다.
- **랭킹 조회도 호출 예산과 입력 단위를 지킨다**: 페이지 상한이 무시되고 최대 2페이지(≈60건)만 오는 경로가 있고,
  구간 하한/상한을 **정수**로 요구하는 경로도 있다(문자열 `2.0` → `invalid_input`). 발표된 “상위 200”이 실제로
  60건일 수 있으니 받은 건수를 로그에 남긴다.
