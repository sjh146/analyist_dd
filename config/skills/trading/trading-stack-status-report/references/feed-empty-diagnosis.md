# 피드가 비었을 때 진단 (전략별 후보 0건)

발행기는 후보가 비면 **의도적으로 조용히** 비운다(경고는 발행 로그에만 남는다) — '발행 완료' 로그가 있어도 그 전략은 0건일 수 있다.
`/health` 의 `items.<전략>` 이 0이면 아래 순서로 내려가며, 어느 단계에서 끊겼는지 확인한 뒤에만 조치한다.

## 1. 발행 로그 (`reports/cron_feed_publish.log`)

- `점수 퇴화 — n/m건이 동일값 X → 이 전략은 빈 리스트로 발행` = 발행기의 퇴화 가드가 작동한 것. 방어는 정상, **원인은 스크리너 쪽**이다.
- `산출물 기준일 ... (N일 전)` + 그 전략 0건 = 낡은 산출물 가드.
- `후보 0건` = 스크리너 산출물 자체가 비었다 → 2번.
- `score min=.. median=.. max=.. spread=..` 가 살아 있으면(예: spread 6~8) 그 전략은 사용 가능.

## 2. 스크리너 산출물 (`reports/<전략>_latest.json`)

- `batch_type: raw_fallback` + `high_confidence: 0` = 임계값 이상 실시그널이 하나도 없었다는 뜻(모델 출력이 눌린 상태).
  **챔피언을 방금 승격한 직후라면 이 상태를 '스크리너 결함'이 아니라 승격의 부작용으로 의심하라**: 승격 시각
  (`services/xgboost-ml/app/models/champion/auc.txt` 의 mtime·승격 커밋)과 피드 `generated_at` 을 대조하고,
  발행 로그의 제외 줄(`[<전략>] confidence < 0.50 후보 N건 제외`)에서 *N = 그 전략 후보 전량*이면 원인은 발행기가
  아니라 모델 출력이다 — 피드 후보 0건은 정상 동작이고, 조치는 문턱을 낮추는 것이 아니라 엔지니어에게
  모델/피처 환류를 올리는 것이다.
- `confidence` 분포를 본다: 거의 한 값(예: 0.50~0.54)에 몰려 있으면 문턱·상위 N 선별이 사실상 무작위다.
- `auc` 와 `generated_at` 도 함께: AUC 가 학습 이력과 다르면 챔피언이 갱신되지 않았다는 신호.

## 3. 파이프라인 로그 (`reports/full_pipeline_<ts>.log`) — 점수 뭉침의 실제 출처

- Phase 2(ML 학습)에 `Traceback ... train_quick.py` 가 있고 `Best AUC:` 가 빈 값이면 **챔피언이 갱신되지 않았다**.
  학습 스크립트와 트레이너의 반환 시그니처가 어긋나는 계열의 오류(`ValueError: too many values to unpack (expected N)`)가 대표적이다.
  수정은 트레이너가 실제로 돌려주는 값 개수에 맞춰 언패킹하는 것 — **검증 전에는 그 전략의 피드를 켜지 않는다.**
- Phase 3 끝줄 `Swing analysis saved: N stocks, a UP, b DOWN` 에서 `a` 가 한 자리 수면 모델이 상수 출력(N-1 DOWN)을 내는 상태다. 이 목록은 피드로 내보내면 안 된다.
- 같은 로그에서 `bayes_factors artifact not found` / `compute called before fit()` 경고가 반복되면 피처 일부가 상수 0 으로 들어가고 있다는 뜻(학습 품질 저하).

## 4. 데이터 기준일

스크리너가 읽은 최신 거래일이 오늘인지 전일인지, 거래정지 행(시·고·저 0)이 섞였는지 확인한다.
공식 일봉 경로는 D-1/D-2 반영이므로 **전일 기준 후보 + 당일 지정가** 괴리가 생긴다 — 발행기가 맞춘 가격이 신호 시점 종가인지 확인한다.

## 5. 조치 결정

- score spread 가 살아 있는 전략은 그대로 사용 가능하다.
- 점수 뭉침이 남아 있는 전략은 **빈 채로 두는 것이 정상**이다. 억지 발행 플래그(`--allow-degenerate-scores`)로 문턱을 우회하지 않는다 — 선별이 무작위인 목록을 실거래에 넘기게 된다.
- 순서: 원인 수정 → 재학습·재스크리닝 → `batch_type: signal` + confidence 분포 확인 → 그 다음에 발행을 켠다.
