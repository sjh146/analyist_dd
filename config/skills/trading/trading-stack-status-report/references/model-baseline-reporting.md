# AUC·피처 수치를 보고할 때의 기준선 규칙

모델 성능 숫자를 인용하는 순간(상태 보고·승격 판정·실험 결과) 항상 붙는 전제다.

## 1. AUC 에는 패널 파일명·종목수를 반드시 붙인다

같은 라벨(h=5·q0.30·top30)·같은 하네스에서도 **패널 유니버스가 다르면 기준선이 뒤집힌다**:

| 패널 | 종목수 | AUC |
|---|---|---|
| 좁은 패널 | 49 | 0.5405 ± 0.0331 |
| 유동성 패널 | 200 | **0.5107 ± 0.1059** (5폴드×3시드, 12,839행) |

좁은 패널이 0.03 높고 폴드 분산은 1/3이다. 그래서 "0.5405 vs 챔피언 0.5513"처럼 **서로 다른 패널의
수치를 나란히 놓으면 승격 판정이 뒤집힌다**. 보고·판정에는 `panel_<N>liq_<...>` 이름을 함께 쓰고,
새 측정은 프로덕션 유니버스에 가까운 **넓은 패널**에서 한다(좁은 패널의 우위는 넓은 유니버스에서 재현되지 않는다).

판정 자체는 단일 분할 운값이 아니라 **확장창 walk-forward 다중 폴드 평균**으로 한다(사용자 기준).

## 2. 피처 수 변화는 '플래그 OFF 기본값'으로 보고한다

새 피처 축은 env 플래그로 opt-in 시킨다(`US_MARKET_FEATURES` 패턴):

- OFF = 기존 피처 수 그대로(199), ON = +7(206). **OFF 에서 행렬 불변을 실측**한 뒤 배선 완료라고 쓴다.
- as-of 조인은 `trade_date < t` 의 **마지막 세션**(같은 날 값 금지 — look-ahead), 소스 결손은 0.0 fail-open.
- 플래그 ON 은 **챔피언 재학습 + 패널 재빌드가 선행 조건**이므로 '피처 추가 완료'가 아니라
  '배선 완료·미적용'으로 보고한다.

## 3. 데이터 축은 '수리'와 '축적'을 구분한다

파이프라인 버그를 고쳐도(예: 뉴스 귀속 46→62종목, 보존 2→90일) 감성·이벤트 피처는 표본이 쌓여야 분산이 생긴다.
**커버리지가 차기 전에 패널을 재빌드하면 죽은 피처가 남은 패널이 새 기준선으로 굳는다.** 축적 대기 항목은
'측정 가능 시점'과 함께 백로그에 남기고, 그 사이의 AUC 변화는 기준선 변경으로 해석하지 않는다.

## 4. 죽은 피처·상수 피처는 성능 숫자와 함께 센다

실측 예: 202피처 중 죽음 38(감성 7/7, 이벤트 12/18), 상수 37. "AUC 0.51" 만 보고하면 이 상태를 숨기게 된다 —
죽은 피처 수와 표본(세션 수)을 같은 줄에 적는다.
