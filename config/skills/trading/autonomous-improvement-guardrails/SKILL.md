# autonomous-improvement-guardrails

자율 루프가 **스스로 코드를 바꾸거나 자기 우선순위를 정하게** 만들 때(또는 그런 경로를 새로 붙일 때)의 절차와 함정.
이 클래스의 사고는 대부분 **조용한 오염**으로 나타난다(측정값이 미세하게 틀리거나, 경로가 아무 것도 안 하거나).
그래서 규칙은 '무엇을 한다'보다 **'어떤 입구를 닫고 무엇으로 검증하는가'** 에 집중한다.

## 절차 — 새 자율 개선 경로를 붙일 때

1. **경로를 먼저 나눠라**: 읽기(감사·측정) / 쓰기(코드·정책·피드 계약). **쓰기 경로만** 격리·검사·검증·되돌리기가 필요하다.
   읽기 전용 경로에 격리 비용을 쓰지 말고, 쓰기 경로를 읽기처럼 다루지도 말라.
2. **격리**: 작업 사본(worktree)에서만 쓰게 한다. 리포 작업트리에 직접 쓰는 경로는 격리·검증·되돌리기 중 하나가 빠져 있다.
3. **금지 경로 검사**: 단일 진실원 모듈 하나에 `FORBIDDEN` 토큰 + **사유**를 정의하고, **모든 쓰기 입구가 그 모듈을 부른다**
   (오케스트레이터·역할이 직접 부르는 저작 도구·셸 위임 래퍼까지). 셸 입구에는 CLI(금지면 rc=2)로 노출한다.
4. **검증 3단**: ① 산출물 존재 ② 구문/정적 검사 ③ 항목별 check. **위임 결과는 자기신고와 동급**이다 —
   파일이 실제로 있는지, 직접 컴파일되는지, 실행되는지까지 본다.
5. **과제당 1커밋 + 되돌리기 명령 기록**(revert sha). 묶음 커밋은 되돌리기를 불가능하게 만든다.
6. **거부 ≠ 실패**: 부하·락·가드로 인한 거부 코드는 **정상 직렬화**다. 실패로 기록하거나 반복 기동하지 말고,
   거부 시 남은 흔적(pidfile·state)을 지워 '실행 중'과 구분되게 한다.
7. **첫 발동은 안전한 대상으로**: 한 번도 실행된 적 없는 경로는 문서·`_*.py` 같은 무해한 대상으로 **실제로 태워**
   3단 검증을 통과시킨 뒤에야 실전 대상을 허용한다.

실돈 경로를 **무한 루프로 개선**하는 형태(5분 읽기 전용 감사 + 매일 개선 큐 + 수정은 큐를 거쳐 검증)는
`references/live-path-audit-loop.md` 를 따른다 — 감사가 잡아야 하는 불변식 표(브로커∖저널, 미체결 주문, 손절 미발동,
유동성 하한, 피드 필드 누락)와 "필드 부재 ≠ 값 미달" 판정 규칙이 들어 있다.

## 코드 품질은 래칫으로 강제한다 (사용자 상시 규칙)

루프가 코드를 쓰는 저장소에서는 **주석을 금지**하고 린트로 막는다 — 주석은 코드와 어긋난 뒤에도 에이전트의 근거로 쓰여
오판을 만든다. 규칙: ① 코드 `#` 주석 금지(기계 지시자만) ② `TODO` 는 티켓 ID 필수 ③ `except` 삼킴·로그 없는 기본값 반환 금지.
**기존 부채는 파일별 기준선으로 고정하고 증가분만 차단**하며(신규 파일은 허용 0), 집행은 pre-commit 훅 + 야간 크론 +
역할 규약 문서 세 곳에 둔다. 절차·판정식·함정(`git add -A` 실패, `uvx ruff`, `_*.py` 제외, AST 의 SyntaxWarning)은
`references/code-quality-gates.md` 를 따른다. 역할 간 인계를 계약 JSON 으로 옮기는 방법도 같은 문서에 있다.

## 함정 (각각 실측으로 확인된 것)

- **금지 목록이 여러 곳에 복제되면 그중 하나가 입구가 된다** → 목록을 공유시키고, **토큰 드리프트를 테스트로 잠가라**
  (다른 목록에 없는 토큰이 있으면 테스트 실패). '검사는 하고 있다'는 착각이 가장 흔한 구멍이다.
- **가드가 예외로 죽으면 조용히 무력화된다** → 가드를 못 불러오면 **fail-closed**(쓰기 금지)로 두고 사유를 기록한다.
  자율 쓰기는 드물어서 막혀도 손해가 작고, 침묵 사고는 크다.
- **사람 승인 요청까지 차단하면 우회를 부른다** → 결정/위임에서 금지 대상은 **'실행'만 차단**하고,
  `escalations`(승인 요청)로 적는 것은 허용하라. 금지 대상 변경을 지시하는 어휘('변경'·'적용'·'실행'·'승격 실행')를
  검사 대상 어휘 목록에 포함시킨다.
- **위임 백엔드는 rc=0 이면서 0바이트를 낼 수 있다** → 어느 백엔드가 답했는지 마커를 남기고,
  '성공 = 최소 바이트' 조건으로 폴백이 실제로 걸리는지 확인한다. 백엔드 하나만 보고 성공이라 쓰지 않는다.
- **위임 잡음은 커밋에서 빼라**: 에이전트가 남기는 `.backend`·`.stderr.*` 류가 산출물과 함께 커밋되면 리포가 오염된다
  → 커밋 직전 `git reset -q -- <pathspec>` 로 제외하고 `.gitignore` 에도 등록한다.
- **결정권(페르소나)을 줄 때는 헌장을 코드로 강제하라**: ① 근거(실측 수치) 없는 결정은 **기록 거부**
  ② 금지 대상 변경은 결정이 아니라 에스컬레이션 ③ 결정 기록은 append-only + 기계가 읽는 스키마
  ④ 주 1회 자기심사('내가 고른 레버가 목표 지표를 움직였나?'). 문구만 있는 헌장은 지켜지지 않는다.
- **기록된 권한 ≠ 실제 권한**: 쿼터·킬·우선순위를 기록만 하고 **실행 자원(야간 작업량)에 배선하지 않으면 장식**이다.
  결정 파일을 실행기(오케스트레이터)가 **상한으로 읽게** 만들고, 그 배선을 테스트로 잠가라.
  같은 유형이 권한 밖의 설정에서도 나온다 — **위험 파라미터(동시보유 슬롯·노출 한도·문턱)를 바꿀 때는 3단을 분리해 적어라**:
  ① 규칙·설정·테스트(정의) → ② 실행 경로 배선 → ③ 실측 검증. **①만 끝난 상태를 '동작함'으로 보고하지 않는다**
  (예: 슬롯 규칙 모듈과 설정 필드는 들어갔지만 진입 게이트가 아직 안 읽으면 동작은 그대로다).
  실주문·노출 경로는 이 순서를 지켜야 검증 불가능한 반쪽 변경이 라이브에 안 들어간다.
- **탐색 루프의 진행 기록은 '데이터 지문'으로 키를 잡아라**: 조합 키만으로 '이미 평가됨'을 관리하면
  새 데이터가 쌓여도 전부 건너뛰어 **자율 탐색이 죽은 루프**가 된다(지문 = 대상 파일 크기·mtime·세션 수).
- **체결·접근 불가 조건은 탐색 축이 아니라 필수 조건이다**: 격자에 '무필터' 값을 축으로 넣으면 살 수 없는 대상이
  만든 착시 수치가 '통과'로 판정된다 → 축에서 제거하고, 판정 함수에서도 상한 초과를 무조건 탈락시킨다(방어 2중).
- **캐시는 '값 불변'을 객체 지문으로 검증하라**: 측정용 패널·중간산출물을 디스크에 캐시할 때
  ① 캐시 없이 빌드 ② 빌드+저장 ③ 재로드 → 결과 객체 digest 3자 일치를 확인한다. 지표를 두 번 돌려 비교하는 것은
  작은 격자에선 측정 불가(None)가 되고 큰 격자에선 비싸다. 캐시 키에 **행/조합 집합 지문**을 반드시 포함하라
  (크로스섹션 랭크처럼 '그 집합 위에서' 계산되는 값은 집합이 다르면 재사용하면 안 된다).
- **과거 시점을 지원하지 않는 API/도구는 조용한 0 대신 명시적 거부로**: 사후 복구가 불가능한 작업(당일만 제공되는
  조회 등)은 '0건'으로 끝내면 '비용 0'처럼 오독된다 → 과거/미래 파라미터를 거부(rc≠0 + 사유)하고,
  그 작업을 **정작 할 수 있는 시점에 도는 스케줄**로 옮긴다(휴장·미연결이면 건너뛰고, 실패만 알린다).
- **비UTF8 콘솔에서 비ASCII 출력이 죽으면 도구가 '아무 일도 안 한 것'처럼 보인다** → Windows 콘솔용 스크립트는
  시작 시 stdout/stderr 를 UTF-8(errors=replace)로 재설정한다.
- **같은 설정으로 두 번 실패한 잡은 세 번째를 돌리지 마라**: 산출물이 0인 채 죽는 잡(무증상 사망)은 재시도로
  풀리지 않는다 — 다음 수단은 **범위 축소(유니버스·격자)나 단위별 체크포인트**다. 끝에만 산출물을 쓰는 잡은
  중간 체크포인트가 없으면 한 번의 사망으로 전부 손실이다(실측: 같은 스크립트 3회 연속 산출물 0 — 3회차는 같은 설정이었고,
  남은 수단은 폴드별 체크포인트/유니버스 축소였다). 기동 rc 는 '시작했다'는 뜻일 뿐이므로 생존은 로그 **바이트 증가**로 본다.
- **컨테이너가 긴 작업을 호스팅할 때**: 세션과 함께 죽지 않게 컨테이너 안에서 분리 실행하고,
  이미지에 `ps`/`pgrep` 이 없을 수 있으니 `/proc/<pid>/cmdline` 스캔으로 확인한다(스캔 루프는 자기 자신을 매칭하므로
  자기 pid 를 먼저 건너뛴다). 셸 `timeout` 은 컨테이너 안 프로세스를 죽이지 않는다 — 명시적으로 종료하고 확인 후 다음을 띄운다.

## 사용자 보고 규칙

- **음(−) 결과도 결과다**: 통과 0개·재현 실패를 그대로 쓰고 문턱을 낮추거나 지표를 바꾸지 않는다.
  '무엇이 안 되는지'가 자산이고, 그걸 숨기면 다음 세션이 같은 실험을 다시 돈다.
- **성장은 소수의 숫자로만 말한다**: 목표 지표(체결 가능 순기대 · 풀/벤치마크 대비 초과) · 거래 발생일 수 ·
  비용 계상 여부 · 실현 손익. 부수 활동량(실행 건수·커밋 수)을 성과로 제시하지 않는다.
- **사람 단계는 에스컬레이션으로**: 대행 불가한 것(대화형 로그인·관리자 권한)은 정확한 명령 한 줄 + 완료 검증 방법 +
  마감 시각을 함께 적는다. 그리고 '완전 무인'의 상한을 매번 명시해 과장하지 않는다.
