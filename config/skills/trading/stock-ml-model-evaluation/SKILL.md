# 방향성 주식 ML 모델 학습·평가·승격

한국 주식 피처로 "다음날 방향" 예측 모델을 학습·평가·승격할 때의 규칙.
레포별 절차는 그 레포 문서가 갖고, 여기에는 **모델 선택·측정·승격에 재사용되는 규칙**만 둔다.

## 0. 계약부터 확인한다

- 산출물 계약(`feature_names.json` = 추론 벡터 순서, `auc.txt`, `training-result-*.json`)을 읽고 **학습과 추론이 같은 순서**를 쓰는지 확인한다. 학습 A순서·추론 B순서면 확률이 0.5 근처로 붕괴한다(0-fill 누락도 같은 증상). 스크리너가 json 순서로 벡터를 만들면 학습도 그 순서로 만들어야 한다.
- **학습·스모크 스크립트가 라이브 모델 디렉터리에 직접 쓰게 두지 않는다.** 산출물은 항상 후보 디렉터리(`models/quick_validation`, `models/exp_*`, `models/champion_cand`)로 보내고, 라이브 모델 교체는 전용 승격 모듈로만 한다. 소수 종목 스모크 모델이 라이브 모델을 대체하면 스크리너 확률이 붕괴해 신호가 조용히 빈다.
- CLI 인자를 모델 생성자에 **실제로 전달되는지** 확인한다. `--seed`/`--n-estimators`가 argparse에만 있고 모델 생성자에 안 넘어가면 튜닝이 무효이고 멀티시드 측정 자체가 불가능해진다.

## 1. 측정 프로토콜 (단일 split 금지)

1. **시드 0~4 평균±std**로 판정한다. 단일 시드 최고값은 쓰지 않는다.
2. **워크포워드 평균**(창/스텝/purge 고정, 훈련=과거·평가=미래)을 함께 낸다.
3. **최근 N거래일 OOS 패널 AUC** — 후보와 현 라이브 모델을 **같은 프로토콜·같은 날짜**로 나란히 측정한다(하네스에 `--model-dir`를 넣어 두면 후보 비교가 1줄이 된다).
4. 최종 후보는 **수익 시뮬레이션**(수수료·거래세·슬리피지, 보유기간, MDD·샤프·승률)까지 돌린다 — AUC는 순위 지표일 뿐 수익성이 아니다.
5. 보고는 **시드별 값 + 평균±std + 구간 OOS + 실행 명령**을 함께 낸다. 단일 숫자만 보고하지 않는다.
6. **판정 문턱을 실행 전에 못 박는다.** 폴드 간 표준편차가 ±0.03 규모면 **+0.02 이상**만 개선으로 인정하고,
   그 미만은 노이즈로 보고한다(실측: 새 데이터 투입 후 +0.0046 → 문턱 미달로 "변화 없음" 판정).
   문턱을 사전에 정해두면 결과를 보고 나서 "올랐다"고 말하는 자기기만을 막는다.
7. **폴드 std 가 작은 것을 개선으로 읽지 마라.** 시장상대 이진 라벨은 std 가 기준의 절반(0.016 vs 0.037)이었지만
   평균은 더 낮았다(0.522 vs 0.538). 안정성과 성능은 다른 축이고, 판정은 **평균**으로 하고 std 는 신뢰구간으로만 쓴다.
8. **"이 축은 이미 검증됐다"고 말하기 전에 드라이버를 grep 한다.** 하네스에 **구현만 되고 호출되지 않는 분기**가
   있으면 그 축은 측정된 적이 없다(실측: 라벨 생성 함수에 `kind="relative"`(시장상대)가 있었지만 main 은
   `"quantile"` 만 호출 → 시장상대 라벨은 walk-forward 에서 한 번도 측정되지 않은 상태였다).
   실험 목록을 읽을 때는 인자 이름이 아니라 **main 이 실제로 넘기는 값**을 본다.

## 2. 선택 편향 경계

- 같은 test split에서 N개 설정을 스윕해 뽑은 최고값은 성능이 아니라 **최댓값 통계**다. 같은 설정에서도 구간에 따라 0.44~0.61이 나온다(실측). **과거 최고 AUC를 목표치로 삼지 않는다** — 목표는 반복 측정에서 재현되는 평균이다.
- 성능 수치를 옮길 때는 **설정·데이터 구간·표본 크기를 함께** 붙인다. 서로 다른 split의 숫자를 나란히 놓고 "개선"이라 말하지 않는다.
- **자동 스윕은 격자를 코드에 사전등록하고 결과를 registry(키=조합)에 남겨라.** 같은 데이터로 같은 조합을 다시 재는 것은
  새 증거가 아니고, 격자를 사후에 늘리면 그건 새 프로토콜이다. 비교 기준선은 **같은 데이터 안의 현행 설정**으로 두고
  (다른 파일·다른 모집단의 값과 나란히 놓지 않는다), **통과 0개도 정상 산출물**로 보고한다 — 축을 사후에 늘려
  '뭔가 찾았다'고 말하지 않는다.

## 3. 승격 게이트 설계

- 게이트는 **절대 하한 + 비열화** 두 조건으로 둔다(예: 후보 평균 val AUC ≥ floor AND 현 모델 이상). 통과 시에만 교체하고, **교체 전 라이브 모델을 타임스탬프 백업**한다(최근 N개 유지).
- 교체 후 **되돌리기 한 줄**(백업 복원 명령)과 백업 경로를 보고에 포함한다.
- **하한 하나로만 판단하면 더 나은 후보를 놓친다.** 검증(val) 점수와 실전(최근 구간 OOS) 점수는 엇갈릴 수 있다(실측: val 0.506으로 게이트 미달인 후보가 OOS 0.5395, 현 챔피언 OOS 0.4924). 승격 판단에는 두 지표를 함께 붙이고, 게이트가 val만 보는 경우 그 한계를 보고한다.
- 자율 루프에 승격을 넣을 때는 **게이트 통과 시에만** 하도록 하고, 미달 후보는 조용히 버리지 말고 사유를 로그·결과 파일에 남긴다.
- **라이브 성과로 승격을 판정할 때는 훈련 구간 세션을 빼고 OOS 세션만으로 재계산하라.** 라이브 저널 전체를
  합산하면 챔피언이 학습한 구간이 섞여 성과가 낙관적으로 나온다(실측: 챔피언 세션 기대값이 전체 −0.182%/세션 →
  `train_end` 이후만 보면 **−0.768%/세션(t −2.05, n=25)**). 기준선은 "OOS 세션 n≥20 AND 기대값>0 AND t≥1" 처럼
  표본·부호·유의성을 한 줄에 묶어 사전에 박고, 미달이면 **BLOCK 사유를 숫자로** 출력한다.
- **재배포 게이트를 실주문 경로에 자동 잠금으로 넣지 마라.** 게이트는 "지금 배포하면 안 된다"를 리포트하는
  판정 장치이고(주문 함수 안에 조건을 심으면 오작동 시 매매가 멈추고 원인 분리가 안 된다), 실제 중단은
  halt/kill_switch 의 책임으로 둔다. 게이트 스크립트는 저널·OOS 결과 파일만 **읽어서** 판정하고 DB·주문에 쓰지 않는다.

## 4. 피처 생존 감사 (죽은 피처)

- **"전부 0"과 "결측"을 먼저 구분하라.** `null_ratio 0.0` 인데 `std 0` 이면 데이터가 없는 게 아니라 **빌더가
  `fillna(0)` 으로 덮은 것**이다(실측: dead 24개가 전부 이 모양). 모델은 "정보 없음"과 "참값 0"을 구분할 수 없어
  트리 분기도 못 한다 → 처방은 재빌드가 아니라 **결측을 NaN 으로 유지 + 결측 지시자 피처 추가**다.
  전량 NaN(진짜 결측) / 상수 0 / 희박(nnz<임계) / 횡단면 상수를 클래스로 나눠 보고해야 조치가 갈린다.
- **원천 커버리지는 전역 행수가 아니라 "패널 유니버스 × 패널 기간"으로 재라.** 테이블이 수십만 행이어도 그중
  패널 종목은 27/200, 패널 기간 내로 좁히면 4/200 일 수 있다(뉴스·SNS 는 기사·게시글 등장 종목 기준으로 쌓인다).
  소스 시작일과 패널 빌드 시각도 나란히 놓아라 — 뉴스가 2026-04 시작인데 패널이 2025-08~이면 앞 60%는
  원천이 존재하지 않았던 구간이다. 진단 형태:
  `select count(distinct stock_code) from <t> where stock_code = ANY(%s) and <date_col> between %s and %s`.
- **희박 이벤트를 nnz 임계(예: 5%)로 "죽었다" 판정하지 마라.** 191/200 종목에 값이 있어도 5일 창 발생률이
  0.02~5% 면 dead 로 찍힌다 — 데이터 부재가 아니라 정의 문제다. 누적 카운트·EWMA·타깃 인코딩·창 확대로
  재정의해 재측정하고, 그 축은 따로 보고한다.
- 피처별 nonzero 비율·분산을 실측해 **죽은 피처 수**를 센다. "그 테이블이 0행이라 그 피처는 죽었다"는 추정 금지 — 간접 소스(집계 테이블·기존 분석 결과)가 값을 낼 수 있다(실측: 뉴스 테이블 0행인데 감성·뉴스 건수 피처는 값이 있었다).
- 죽은 피처가 많으면 **모델 탓이 아니라 데이터 탓**이다. 데이터 수집·정제 경로를 먼저 살린다.
- **데이터를 채울 때는 그 피처를 소비하는 학습·평가 유니버스와 교집합을 맞춰라.** 학습이 특정 선별 함수
  (예: `select_training_universe(pg, limit=200, seed=0)`)로 뽑은 종목만 보는데 임의 그룹(유동성 상위·시총 상위·
  관심종목)을 채우면 커버리지 표만 예배지고 **학습 표본에서는 그 피처가 영구히 0** 이다. 착수 전에 학습 대상을
  파일로 뽑아 교집합을 세고, 채운 뒤 “학습 유니버스에서 비영인지”를 다시 확인한다.
- **패널·피처 캐시를 먼저 무효화하라.** 새 데이터를 적재하고 **낡은 캐시 패널**로 평가하면 새 피처가 0 인 표본을
  측정해 “효과 없음”으로 결론낸다. 측정 전 캐시를 지우거나 재빌드하고, 보고에 패널 빌드 시각을 적는다.
- **캐시 키에 들어가지 않는 인자를 바꾸면 조용히 다른 표본을 측정한다.** 캐시 경로가 `--days` 로만 결정되는
  하네스에서 `--limit`(유니버스 종목수)을 바꿔 실행하면 이전 유니버스의 패널을 그대로 재사용한다 — 종목을 3배로
  늘린 실험이 실제로는 옛 50종목 패널을 돌린다. 실험을 걸기 전에 **하네스의 캐시 키를 읽고**, 키에 없는 축을
  바꿀 때는 별도 캐시 경로를 명시한다(삭제 대신 rename 으로 남기면 되돌릴 수 있다).
- **측정용 캐시(실험 산출물이 아닌 가속용)의 키에는 '행 집합 지문'까지 넣어라.** 횡단면 rank 를 주입하는 측정은
  그 날의 종목 집합에 의존하므로, 같은 기간이어도 집합이 다르면 재사용이 값을 바꾼다. HIT/MISS 를 항상 로그에
  남기고(조용한 재사용 금지) 저장은 tmp→원자적 교체, 손상 시 재빌드, 탈출구(`--no-panel-cache`)를 둔다.
  **캐시가 값을 바꾸지 않았음을 증명하라**: 같은 행 집합을 ① 캐시 없이 신규 빌드 ② 캐시 저장 ③ 캐시 재로드 로 돌려
  **피처 해시 3자가 같은지** 비교한다 — 작은 격자를 두 번 돌려 지표를 눈으로 보는 방식은 그 격자가 값을 못 내면
  전부 None 이라 아무것도 검증하지 못한다.
- **새 피처 계열의 임팩트는 패널을 재빌드하지 말고 컬럼을 덧붙여 측정한다.** 기존 패널을 로드해 조인으로
  새 계열 컬럼만 append 후 재저장하면, 같은 행·같은 다른 피처 위에서 델타가 곧 그 계열의 기여다. 재빌드는
  몇 시간이 걸리고 그 사이 캐시 무효화·유니버스 변경으로 통제가 깨진다. 단 이 패널은 **실험 산출물**이다 —
  운영 피처 계약(순서·목록)과 다르므로 승격 경로에는 그대로 쓰지 않는다). 컬럼 패치는 **자기검증을 내장**한다:
  ① 출력 파일 ≠ 입력 파일(원본 덮어쓰기 금지) ② `X.shape[0]`·`dates`·`codes` 가 원본과 동일 ③ **대상 컬럼 외
  모든 컬럼이 바이트 단위로 동일**(`np.array_equal`) ④ 대상 컬럼 nnz 가 패치 후 실제로 늘었는가.
  조인은 **거래일 lag 와 최신성 가드**를 명시한다(공매도 데이터는 T+1 → `asof_values(lag_trading_days=1)`;
  원천 최신일이 대상일보다 N일 이상 낡으면 그 행은 NaN 으로 두고 몇 행인지 센다).
- **평가를 걸기 전에 새 계열의 밀도(비영 비율·종목당 유니크)를 먼저 잽다.** 원천 테이블이 채워졌어도 이벤트성
  피처는 대부분 0 이라 신호가 나올 수 없다 — 실측: 새로 만든 17컬럼 중 8개가 전량 0(원천 카테고리 미수집),
  나머지도 비영 0.1~5%. 희소하면 평가 전에 ① 원천 범주 수집을 완주하고 ② 희소 이벤트를 밀도 높은 묶음
  (자금조달·지배구조·영업)으로 재구성한다. 밀도를 모르고 돌린 평가는 "신호 없음"을 **데이터 부족**과
  구별하지 못하고, “전부 0 인 컬럼이 섞인 행렬”을 학습에 넣으면 정보 없이 차원만 늘어난다.
- **"새 데이터가 효과 없다"를 결론내기 전에, 그 피처가 선별 창에 들어갈 수 있는지부터 잰다.** 학습이 상위 K개
  (예: top30)를 **학습 구간의 단변량 edge** 로 뽑으면, 신규 피처의 edge 가 그 문턱보다 작으면 **모델에 들어갈
  기회 자체가 없다** — AUC 가 안 움직인 것은 당연하고 원인은 데이터가 아니라 선별이다. 실측: 신규 4그룹
  (수급·공매도·프로그램·파생) edge 0.0002~0.0112 vs top30 문턱 0.044(약 1/4) → 하나도 선별되지 않았고
  AUC 델타는 노이즈(+0.0046)였다. 보고는 "효과 없음"이 아니라 **"선별되지 않음(문턱 대비 얼마)"** 으로 적는다.
- **날짜 내 횡단면 분산이 0인 피처는 횡단면 순위 모델에서 원리적으로 무용하다.** 시장 전체 값(지수·금리·환율·
  프로그램·파생·사이클)을 종목별 피처로 복제하면 그날 모든 종목이 같은 값이 되어 순위를 가를 정보가 없다
  (실측: 210피처 중 34개, 해당 그룹 edge 전부 0.0002). `df.groupby(date).std()` 로 0인 열을 세어 **레짐 게이트로
  격리**하고 피처 행렬에서는 뺀다 — 정규화(횡단면 rank/z-score)해도 되살아나지 않는다.
- **피처명 중복과 전량 0 열을 계약 단계에서 검사한다.** `len(set(names)) != len(names)` 이면 상호작용 피처가
  두 번 들어간 것이고(실측 14개 중복), 같은 신호가 두 열로 세어져 중요도가 부풀고 나머지가 희석된다.
  죽은 피처(전량 0)와 함께 계약에서 정리하는 것이 모델을 바꾸는 것보다 먼저다.
- 로컬 GPU가 없어도 **LLM API 경로로 채울 수 있다**(규칙 우선 필터 → 애매한 10~20%만 LLM 호출). 과거 데이터 소급은 소스의 기간 필터로 수집한다(예: 뉴스 RSS `after:`/`before:` + 종목명 질의, 질의당 100건 상한 → 종목×2주 창 분할). **호출 상한과 비용 로그를 먼저 설계**하고 상한 도달 시 스스로 멈추게 한다.
- 개선 효과는 **죽은 피처 수 시계열**로 추적한다. 채우기 전후 같은 설정을 재학습해 델타를 낸다.
- **재빌드보다 원천 감사가 먼저다.** 패널을 6~8시간 다시 빌드해도 원천이 비어 있으면 아무것도 안 살아난다
  (실측: 재빌드 후 상수 0 → 희박으로 이동한 12개가 전부 nnz 0.02% 수준, 실질 부활 0개). 판정 순서:
  ① `select count(*) filter (where <col> is not null), count(*) from <table>` 로 **값이 있는지**
  ② `stock_code = ANY(<패널코드>)` 로 **패널 종목에 있는지** ③ `information_schema.tables` 로 **그 테이블이 존재하는지**
  ④ 그래도 0 이면 빌더 SQL 을 읽어 **다른 테이블을 조회하는지**. 이 넷 중 하나가 "아니오"면 재빌드는 무의미하다.
- **상수 0 의 정체는 대개 `except: feature = 0.0` 폴백이다.** 빌더가 **존재하지 않는 테이블**(`short_interest`,
  `margin_balance`, `credit_balance` 류)을 조회하고 예외를 삼킨 뒤 0.0 을 채우면, 죽은 피처가 코드 버그처럼 보이지만
  실제로는 **원천 부재**다. `grep -n "= 0.0" <builder>.py` 로 폴백 지점을 열거하고, 각 피처마다 ① 원천 존재
  ② 원천 값 채워짐 ③ 그 원천을 실제로 제공하는 API 가 있는지까지 확인한 뒤 **폐기/수집기 신설/배선** 중 하나로 결정한다
  (폐기 결정도 문서로 남긴다 — 0 으로 두면 모델이 "정보 없음"과 "참값 0"을 구분하지 못한다).
- **살아난 alive ≠ 쓸모 있음.** nnz 가 임계를 넘긴 직후 **일별 rank-IC(선행 N일 수익률) + 5분위 수익률 단조성**을
  재고, 그 전에는 모델에 넣지 않는다. 실측: 커버리지를 31→193종목으로 올려 nnz 0.02%→6.4% 로 살린 뉴스 피처가
  IC 평균 −0.010(중앙 +0.015, 양수일 56%, 28일) · 5분위 단조성 없음 → 투입 보류. **커버리지 개선과 성능 개선은
  별개의 주장**이고, 후자는 별도 측정 없이는 성립하지 않는다.
- **텍스트에서 종목명을 찾아 결측 연결을 복구하지 마라.** 짧은 일반명사 종목명('남성' 등)이 무관한 기사 본문에
  걸려 오탐이 대량으로 생긴다(실측: 성폭력 기사 본문 → 종목 '남성'). 재연결은 **파서·LLM 이 명시한 종목명**에만
  하고, 텍스트 스캔은 표본 검수에서 정밀도를 확인한 뒤에도 채택하지 않는다(오염된 연결은 죽은 피처보다 나쁘다).

## 5. 흔한 오진

| 증상 | 실제 원인 | 조치 |
|---|---|---|
| val AUC 높은데 OOS 0.5 근처 | 최근 구간 regime shift 또는 라벨 노이즈 | 피처 추가보다 **라벨 재정의**(시장상대 방향·2~3일 호라이즌·변동성 조정) 시도 |
| 확률이 0.5001~0.501 근처에 몰림 | 학습/추론 피처 순서 불일치 또는 무정보 모델 | 계약 순서 점검 → 데이터·라벨 재점검 |
| 모든 설정이 0.51~0.52에 수렴 | 데이터가 담은 신호량 한계 | 튜닝 중단, 데이터·라벨·과제 변경 |
| ACC가 0.5 미만인데 AUC는 0.52 이상 | 클래스 불균형(상승률 46% 등) | ACC로 판단하지 말고 AUC·상위 N 승률을 본다 |
| 커버리지(행수·거래일)는 완전한데 성능 낮음 | 신호 부재·측정 방식 | 데이터 품질을 원인으로 지목하려면 재현 쿼리 근거를 붙인다 |
| 새 데이터를 채웠는데 AUC 변화 없음 | 신규 피처가 선별 문턱 미달 / 캐시 미무효화 / 학습 유니버스와 미교집합 | **선별 창 진입 여부와 횡단면 분산을 먼저 측정**하고, 그 다음에 "신호 없음"이라고 말한다 |
| 라벨 변형·피처 변형을 다 바꿔도 최고값이 안 오름 | 남은 축이 아니라 **과제 난이도**(1일/5일 방향 예측의 정보량 한계) | 설정 스윕을 멈추고 목표치를 재협의한다 — 도달 근거가 없으면 없다고 보고한다 |

## 6. 보고 형식 (이 사용자 기준)

- 먼저 결론(재현 가능/불가, 수치), 그 다음 실험 표(설정·시드별·평균±std·OOS), 그 다음 원인과 번호 매긴 다음 작업.
- 실측하지 않은 수치는 "추정"으로 표기하고, 실측으로 대체할 수 있으면 대체한다.
- "불가" 판정에는 그것을 확정하는 근거(독립 구현 2개 이상의 수렴, 워크포워드, 선택 편향 정량화)를 붙인다.
