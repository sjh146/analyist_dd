## ① 피처별 원인 (전부 실측)

### 1. 그래프 계열이 **구조적으로** 항상 0 — 최대 원인
`feature_pipeline` 는 `GraphDatabase.driver(...)` 가 돌려주는 **BoltDriver** 를 그대로
`GraphFeatures` 에 넘기는데, neo4j 5.27 의 BoltDriver 에는 **`.run()` 메서드가 없다**
(`hasattr(driver,'run') == False`, 실측). 그래서 theme/twin/sector/cycle 질의 4개가
모두 `AttributeError` → `except Exception: pass` 로 삼켜져 **관계 유무와 무관하게 0** 이었다.

추가로 관계/스키마 자체도 비어 있었다(실측 before):
`Theme 20 · HAS_THEME 563 · PART_OF_THEME 0 · TWIN_OF 0 · Sector 0 · BELONGS_TO 0 · Cycle 0`.
- 리더는 `PART_OF_THEME` 를 읽는데 라이터(`services/news-analyzer/app/graph/news_graph_writer.py`)는
  `HAS_THEME` 를 쓴다 → **관계 타입 불일치**.
- 기존 작업노트의 "Theme 0 / HAS_THEME 0" 은 오측정이다(실제 20 / 563).

### 2. 시장폭/수급의 "테이블 없음" — 존재하지 않는 테이블명을 조회
`feature_pipeline._build_advanced_features` 가 `stock_prices` 를 조회하는데 **그런 테이블이
없다**(실제 데이터는 `market_data`). 그 예외가 삼켜져 `sector_momentum`, `market_breadth`,
`days_to_cover` 가 0.
- `krx_total_trading_value` / `krx_advance_decline_ratio` 는 `krx_trading`(0행) 조회 →
  자격증명 블로커 계열 테이블이라 0.

### 3. `market_breadth` 는 뷰를 만들어도 0 — **SQL 자체 버그**
```sql
SELECT COUNT(*) FILTER (WHERE close_price > prev_close), COUNT(*)
FROM (SELECT close_price, LAG(close_price) OVER (PARTITION BY stock_code ORDER BY trade_date) AS prev_close
      FROM stock_prices WHERE trade_date = %s) t
```
`LAG` 가 **당일 행만 남긴 서브쿼리 안**에서 계산되므로 `prev_close` 는 항상 NULL →
`close_price > NULL` 은 NULL → 분자는 언제나 0. (분모는 채워져 0.0/1 = 0.0)

### 4. `krx_advance_decline_ratio` 는 소스가 틀렸다
이름은 상승/하락 비율인데 구현은 `krx_trading` 의 `investor_type='Foreign'` 행
`net_buy / trading_value` 를 읽는다. 외국인 수급 테이블은 자격증명 블로커(0행)이고,
설령 채워져도 ADR 이 아니다. ADR 은 `market_data` 로 계산 가능하다(아래 패치).

### 5. 재무 잔여 — 리더가 리터럴 0.0 / 기간 페어링
- `value_pcr`, `value_ncav`, `value_pfcr`, `quality_cp_to_assets` = **코드에 0.0 하드코딩**.
- `quality_beta` = `self._beta(market_df=None)` 호출 → 항상 0. 게다가 기존 `_beta` 는
  `mkt_rets = stock_rets` 라 `cov(x,x)/var(x) ≡ 1.0`(β 아님).
- **기간 페어링 실측**: `financial_statements` 는 `2026-06-30`(반기 6개월 누적,
  삼성전자 매출 171.5조) + `2025-12-31`/`2024-12-31`(연간, 333.6조)만 있다.
  `_get_financials` 는 `ORDER BY report_date DESC LIMIT 4` 라 latest=반기, prev=연간 →
  성장률/현금흐름 비율이 최대 2배 왜곡. (⚠️ `value_psr`·`momentum_op` 등 **기존 생존
  피처도 이 왜곡을 그대로 갖고 있다** — 담당 밖이라 수정하지 않고 보고만 한다.)
- **`total_debt` 는 실은 "부채총계"** 다(DART ACCOUNT_MAP 확인).
  삼성전자 total_assets − total_debt == total_equity 이므로
  "자산총계 − total_debt" 를 NCAV 로 쓰면 **value_pbr 과 완전 중복**(실측 5종목 모두 소수점
  4자리 일치) → 중복 피처를 넣지 않고 0.0 을 유지했다.

### 6. `economic_events` 가 0행 — 컬럼 부재로 INSERT 가 전부 실패
`services/economic-calendar` 의 `postgres_storage` 가 `INSERT ... source` 를 쓰는데
실제 테이블에는 **`source` 컬럼이 없고** 유니크 제약도 없어서 모든 INSERT 가 에러
(로그만 남기고 실패) → 0행 → `economic_event_*` 상수 0. 추가로 수집기가
`if d < now.date(): continue` 로 **미래 일정만** 만들어 과거 패널 날짜는 구조적으로 0.

### 7. 나머지
- `disclosure_count_5d`: `news_analysis WHERE source='DART' AND analyzed_at >= CURRENT_DATE-5`
  — `source` 는 전부 `google_news`(7728행)이고 **stock_code 컬럼 자체가 없어** 종목별 카운트가
  불가능(전 종목 동일값이 될 수밖에 없는 쿼리).
- `retail_ownership_pct`, `foreign_ownership_pct`, `institution_ownership_pct`: `ownership`
  테이블이 **스키마에 없다**(조회는 실패하고 0).
- `etf_flow_5d`: `etf_flow` 테이블이 **스키마에 없다**. stocks 에 ETF 1175개가 있지만

## ④ 인계할 파이프라인 패치 (`feature_pipeline.py` — 이 작업에서 수정 금지)

```python
# (1) market_breadth — LAG 를 당일 필터 밖에서 계산해야 한다 (line 449-460 대체)
cur.execute("""
    SELECT COUNT(*) FILTER (WHERE close_price > prev_close), COUNT(*)
    FROM (
        SELECT trade_date, close_price,
               LAG(close_price) OVER (PARTITION BY stock_code ORDER BY trade_date) AS prev_close
        FROM stock_prices
        WHERE trade_date <= %s AND trade_date >= %s::date - 14
    ) t
    WHERE trade_date = %s
""", (date, date, date))
# → 기대값: 상승종목비율 0~1 (예: 2026-09-23 약 0.4~0.6)

# (2) krx_advance_decline_ratio — 실제 ADR(상승/하락)로 교체 (line 713-727 대체)
cur.execute("""
    WITH r AS (
        SELECT close_price,
               LAG(close_price) OVER (PARTITION BY stock_code ORDER BY trade_date) AS prev_close
        FROM stock_prices
        WHERE trade_date <= %s AND trade_date >= %s::date - 14
    ), d AS (SELECT * FROM r WHERE trade_date = %s AND prev_close IS NOT NULL)
    SELECT COUNT(*) FILTER (WHERE close_price > prev_close),
           NULLIF(COUNT(*) FILTER (WHERE close_price < prev_close), 0)
    FROM d
""", (date, date, date))
# adv/dec 비율(하락 0이면 NULL → 0.0 처리)

# (3) date 전달 — GraphFeatures 의 시점의존 피처(cycle_up/down, theme_momentum)용 (line 149)
features.update(self.graph.get_graph_features(stock_code, self.neo4j_conn, date))

# (4) disclosure_count_5d — 종목 필터 + 기준일 (sentiment_features.get_disclosure_count 는
#     이미 `date` 를 받도록 고쳐 두었다. 아래 호출부만 패치)
features.update(self.sentiment.get_all_features(stock_code, self.pg_conn, date))
```
`sentiment_features.get_all_features(stock_code, db_conn, date=None)` — **구현 완료**:
`disclosures` 테이블이 있으면 종목·기준일 기준으로 카운트하고, 없으면 0 을 돌려준다.
`graph_features.get_graph_features(..., date=None)` 도 **구현 완료**(date 없으면 기존 동작).
