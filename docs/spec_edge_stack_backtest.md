# 스펙 — 엣지 스택 백테스트 (확률 누적 × 비대칭 손익비)

작성 2026-11-17. **사용자 지시(원문 요지)**: "트레이딩은 미래 예측이 아니라 확률로 수백 번 반복하는 것.
승률이 높다고 수익이 나는 게 아니고, 손실을 작게·수익을 크게 가져가는 위험대비보상이 핵심이다.
승률 40%라도 손실을 작게 관리하면 효과적이다. 엣지는 하나의 지표가 아니라 확률을 쌓아 올리는 것 —
추세확인·지지저항·캔들패턴 등을 결합해 거래 품질을 필터링한다."

이 스펙은 **측정 단계만** 구현한다(실주문 경로 변경 없음). 측정 결과로 임계값을 정한 뒤에만 배선한다.

## 실측 기준선 (재측정 금지 — 오늘 확인된 값)

- 실계좌 11건: 승률 22.2%, 평균이익 1,028원 / 평균손실 5,075원, 기대값 **−2,943원/건**, profit factor 0.058.
  → 손익비는 이익/손실 = 0.203 으로 **역방향**이다(작게 벌고 크게 잃는다).
- 같은 신호 11,300건(OHLC 그리드): 무손절 기준선 평균 −1.328%·승률 36.0%, 7%/7% 중립 −0.822%,
  1%/1% −0.369%, 1%/2% −0.151% → **청산 폭만 바꿔서는 +가 안 된다. 병목은 진입 품질**.
- 왕복비용 0.21%(실체결 검증). 손익분기 승률: ±1% 60.5% · ±1.5% 57.0% · R:R 2(1%/2%) 50.2% ·
  R:R 3(1.5%/4.5%) **43.8%** · R:R 4(1.5%/6%) 40.0%.

## 목표

1. 진입 품질을 **다요인 합의 점수(edge score)** 로 만들고, 점수 문턱별 성과를 실측한다.
2. 청산을 **비대칭 R:R**(손실 작게·이익 크게) 그리드로 실측하고, 승률×손익비의 곱(기대값)으로 판정한다.
3. 워크포워드(전반부 선택 → 후반부 홀드아웃)로 "수백 번 반복" 기준의 표본을 확보하고,
   **양(+) 기대값 + 표본 충분 + 홀드아웃 유지**를 모두 만족하는 조합만 추천한다.

## 데이터·실행 (실측 확정)

- DB: PostgreSQL `127.0.0.1:5434`, db `stock_trading`, user `stock_user`, password 는 `~/analyist_dd/.env` 의
  `POSTGRES_PASSWORD` (스크립트가 `set -a; . .env` 로 읽거나 `os.environ` 사용 — **.env 를 출력하지 말 것**).
- 테이블: `market_data(stock_code, trade_date, open_price, high_price, low_price, close_price, volume, trading_value)`.
- 기간: 2026-04-01 ~ 2026-11-14. `close_price >= 1000`·`open_price > 0` 필터(기존 그리드와 동일).
- 신호 정의(기존 그리드와 동일해 비교 가능해야 함): 신호일 t 에 `chg >= 3%` · `vol_ratio >= 1.5` ·
  `trading_value >= 5억`. 진입은 **t+1 시가**.
- 일봉에는 장중 순서가 없다 → 각 조합마다 **worst(손절 우선) / best(익절 우선)** 두 극단을 계산하고
  중립 = (worst+best)/2 로 보고한다. 이 한계를 MD 첫 단락에 명시(기존 그리드와 같은 규율).

## 엣지 스택 (신호일 t 시점 정보만 — 미래 정보 사용 금지)

각 요인은 `0/1` 이진 판정이고 `edge_score = 합계(0..7)`. 피처별 계산 정의를 코드 주석에 남긴다.

| # | 요인 | 정의(전부 t 이하 데이터) |
|---|---|---|
| 1 | 추세 방향 | `close > MA20` **그리고** `MA5 > MA20` |
| 2 | 추세 기울기 | `MA20` 5일 기울기 > 0 (`MA20_t > MA20_{t-5}`) |
| 3 | 지지저항 돌파 | `close >= 0.98 × HHV20` (20일 고점 2% 이내) 또는 `close > HHV20_{t-1}` |
| 4 | 캔들 품질 | `body/range >= 0.5` **그리고** `close` 가 당일 범위 상위 1/3 |
| 5 | 거래량 확인 | `vol_ratio >= 2.0` |
| 6 | 변동성 적합 | `1.0% <= ATR14/close <= 6.0%` (너무 죽었거나 너무 요동치는 종목 제외) |
| 7 | 과열 회피 | `chg <= 12%` **그리고** 5일 누적 `<= 25%` (추격 금지) |

- `edge_score` 분포를 출력하고, 문턱 `0,3,4,5,6,7` 각각에서 표본 수를 보고한다(문턱별 n 이 100 미만이면
  "표본 부족"으로 표시하고 판정 근거로 쓰지 않는다).

## 청산 그리드 (비대칭 포함, ATR 기반 포함)

고정폭: (1.5,4.5) · (1.5,6) · (2,6) · (1,3) · (1.5,2.5)[기존 지시서 값, 대조군] · (7,7)[현행, 대조군]
ATR 배수: stop=`1.0×ATR14`, tp=`3.0×ATR14`; stop=`1.5×ATR14`, tp=`3.0×ATR14`
(ATR 배수는 종목별 %로 환산해 적용하고, stop 은 `max(0.5%, px)` ~ `min(8%, px)` 로 클램프)

각 조합마다: `n, 승률, 평균이익%, 평균손실%, 손익비(R), 기대값%, 합계%p, profit factor, MaxDD%`.
`손익분기_승률 = (stop + 0.21) / (stop + tp) × 100` 도 함께 출력해 **측정 승률이 이를 넘는지** 표시한다.
(비대칭이면 `p* = (loss + c) / (loss + win)` — 코드 주석에 유도 과정을 남긴다.)

## 워크포워드

- 분할: 1구간 2026-04-01~2026-08-15(선택) / 2구간 2026-08-16~2026-11-14(홀드아웃).
- 1구간에서 **추천 규칙**을 정하고(상위 3개 조합), 2구간은 **재조정 없이** 그대로 적용해 성과를 낸다.
- 추천 조건(모두 만족): ① 중립 기대값 > +0.10%/건 ② 표본 ≥ 300 ③ 2구간 중립 기대값 > 0 ④ 승률이 손익분기_승률 이상.

## 산출물 (계약)

1. `scripts/edge_stack_backtest.py` (신규)
   ```
   python3 scripts/edge_stack_backtest.py [--start 2026-04-01] [--end 2026-11-14] [--json-out ...] [--md-out ...] [--quiet]
   ```
   - psycopg2/numpy/pandas. **DB 는 SELECT 만**. 주문·브리지·트레이더 파일 무접근.
   - 출력: `data/reports/edge_stack_backtest.json` + `.md`. 실행 시각은 넣지 않는다(멱등), `data_range` 만 기록.
2. JSON 스키마:
   ```
   {"data_range": {...}, "signals": {"raw": N, "after_join": N},
    "edge_score_dist": {"0": n, ...},
    "grid": [{"stop":"1.5%","tp":"4.5%","rr":3.0,"threshold":5,
              "worst":{...},"best":{...},"neutral":{...},"breakeven_win_pct":43.8,
              "n":N,"verdict":"..."}, ...],
    "walkforward": {"select_range":..., "holdout":{...}, "picks":[...]},
    "recommendation": {"stop":..., "tp":..., "threshold":..., "why":"...", "limits":[...]}}
   ```
3. MD: 기준선(현행 7/7·승률 22%) → 엣지 점수 분포 → 상위 조합 표(기대값·승률·R·MaxDD·홀드아웃) →
   추천 1개 + 근거 + **한계**(일봉 순서 불확실성, 비용 가정, 표본, 슬리피지 미반영).
