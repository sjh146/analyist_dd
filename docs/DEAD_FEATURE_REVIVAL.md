# 죽은 피처 97개 부활 지도 (실측 기반)

사용자 장기 목표: **"죽은 피처 97개 전부 부활 + 모델 AUC 0.6 돌파"**.
이 문서는 97개가 **왜** 죽었고, 각각을 **무엇으로** 살릴 수 있는지를 실측 근거와 함께 정리한다.

## 측정 (2026-09-25, `feature_coverage` 최신 스냅샷, 총 173 피처)

| 죽음 유형 | 개수 | 의미 |
|---|---|---|
| **전부 0 (`nonzero_ratio = 0`)** | **97** | 값이 하나도 없다 — 미수집 또는 미계산 |
| 종목상수 (유니크값 중앙값 ≤ 1) | 29 | 룩어헤드/스냅샷 의심 (별도 과제) |
| 살아있음 | 47 | 정상 |

## 핵심 진단 — "데이터가 없다"가 아니라 **"계산 파이프라인이 없다"**

죽은 97개 중 **약 43개는 이미 수집된 테이블만으로 오늘 계산 가능**하고, **19개는 원천 수집이
막 시작됐다**. 즉 죽음의 주원인은 데이터 부재가 아니라 **원천 → 피처 변환 코드의 부재**다.
(반례: 재무제표·거시·수급·공매도 테이블은 각각 수천~수십만 행을 이미 보유하고 있다.)

## 실측 검증 (부활 가능성 확인)

```
① DART B 유형 dry-run (2026-08): 3페이지 300건 수신, 적재대상 77~82건/페이지 → 이벤트 공시는 실재
② disclosures 현황: report_nm LIKE '%유상증자%' = 0건  ← A만 수집한 결과 (원인 확정)
③ 키워드 매핑 16종 확정: 유상증자/CB·BW/공급계약/상장폐지/재해/임원변경/소송/M&A/신제품/
   협약/특허/실적/리콜/규제/지분변동/자기주식
```

## 순서 (모델 임팩트 우선)

1. **이벤트 19개** (진행 중) — 공시 이벤트는 단기 방향성과 직결. 오늘 백필 끝나면 분류 스크립트로 즉시 생성.
2. **수급 10개 + 시장·모멘텀 9개** — 계산만 하면 됨(코드 1~2시간).
3. **거시 16개** — as-of 조인 규율 필요(발표 지연 반영).
4. **재무 비율 19개** — 기간유형 구분이 선행 조건이지만 `rcept_dt` 확보로 가능해짐.
5. 각 단계 후 **엔지니어가 로버스트 AUC(다중폴드 평균)로 임팩트 측정** — 신호 없으면 다음 단계.

⚠ 규율: 부활 피처는 **한 번에 한 계열씩** 투입하고 로버스트 AUC로 판정한다(폴드 std ±0.03,
 신호는 기준선 +0.02 이상). 여러 계열을 동시에 넣으면 어느 것이 기여했는지 알 수 없다.
