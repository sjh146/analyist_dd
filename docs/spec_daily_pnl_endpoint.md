## 왜 추가했나

그 결과 시장가 매도 체결가를 호가(bid)로 추정해 저널에 기록했고, 실제와 어긋났다:

## 계약

`GET /daily_pnl` (읽기 전용, 주문·잔고 변경 없음)

```json
{"ok": true, "daily_pnl": {
  "summary": {"eval_pnl": "0", "realized_pnl": "-5", "return_rate": "-1.89"},
  "items": [{"code": "021320", "name": "KCC건설", "buy_qty": "14", "sell_qty": "14",
             "avg_buy_price": "5567", "avg_sell_price": "5548",
             "current_price": "5760", "realized_pnl": "0", "return_rate": "-0.36", ...}]},
 "ts": 1795004307.5}
```

- 값은 전부 **문자열**(Cybos 원본). 수량·가격은 원/주 단위.
- `avg_buy_price`·`avg_sell_price` 는 **원 단위 실측**이므로 저널 청산가 보정에 그대로 쓴다.

## ⚠️ 단위 함정 (미확정)

`realized_pnl` 은 **원 단위가 아니다** — 2026-11-18 4건 실측에서
gross −3,112원 → `-3`, −2,109원 → `-2`, −266원 → `0`, −260원 → `0` 으로 **천원 절사**로 보인다.
따라서:

- `trader_core/fees.py::derive_fees` 는 `realized_pnl` 을 **원 단위로 가정**한다 → 이 응답을
  그대로 넣으면 `fee_total = gross - net` 이 −3,109 처럼 나와 `check(음수비용)` 플래그가 붙는다.
  **원 단위 확인 전에는 derive_fees 에 CpTd6032 값을 직접 넣지 말 것.**
- 확인 방법: 잔고가 큰 날(수십만원 손익) 1건에서 원/천원 여부를 대조하면 확정된다.
  그때까지 저널 보정은 **가격(avg_sell_price) 기반**으로만 하고, 수수료는 기존 기록을 유지한다.
