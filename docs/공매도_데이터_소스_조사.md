# 공매도 데이터 소스 조사 (2026-09-24)

대상: `krx_short_selling` 테이블 → 피처 `short_selling_ratio`, `short_interest_ratio`, `days_to_cover`

## 요약

| 피처 | 리더가 읽는 소스 | 상태 |
|---|---|---|
| `short_selling_ratio` | `krx_short_selling.short_volume / total_volume` | ✅ **살아남** (2,393행 적재, 30종목 × 84거래일) |
| `short_interest_ratio` | `short_interest.short_interest / short_interest.total_shares` (테이블 없음) | ❌ 공매도 **잔고** 소스가 존재하지 않음 |
| `days_to_cover` | `short_interest` + `stock_prices` (뷰) | ❌ 잔고 소스 없음 + **리더 SQL 버그**(아래 3절) |

부수 효과: `alt_features.AlternativeFeatures.short_squeeze` 도 함께 살아났다
(전에는 `krx_short_selling` 2행 미만 → 항상 0. 실측: 042700/402340/034730 2026-09-23 → 1.0).

## 1. 성공한 경로 — KIS OpenAPI 공매도 일별추이

```
GET {KIS_BASE_URL}/uapi/domestic-stock/v1/quotations/daily-short-sale
tr_id: FHPST04830000
params: FID_COND_MRKT_DIV_CODE=J, FID_INPUT_ISCD=<종목>, FID_INPUT_DATE_1/_2=YYYYMMDD
```

실측 응답: **HTTP 200, `rt_cd=0`**, `output1`(현재가 요약) + `output2`(일별 배열).
**1콜 = 요청 구간 전체**(행 수 상한 없음, 실측 65거래일 구간 → 66행), 거래일 **내림차순**.
→ 종목당 1콜로 60거래일 백필이 끝난다(종목별 반복 호출 불필요).

### 필드 매핑 (output2 → krx_short_selling)

| krx_short_selling | KIS output2 | 의미 |
|---|---|---|
| `trade_date` | `stck_bsop_date` | 영업일자 |
| `short_volume` | `ssts_cntg_qty` | 그날 공매도 **체결** 수량 |
| `short_value` | `ssts_tr_pbmn` | 그날 공매도 거래대금 |
| `total_volume` | `acml_vol` | 그날 전체 거래량 |
| `short_ratio` | `ssts_vol_rlim` | 그날 공매도 거래량 비중(%) |

검증(005930, 2026-08-31): KIS `acml_vol`=18,270,969 /
`acml_tr_pbmn`=4,647,038,997,556 이 `market_data.volume` /
`market_data.trading_value` 와 **완전 일치**. 비중 검산
`ssts_cntg_qty/acml_vol` = 1,563,557/18,270,969 = 8.557% ≈ `ssts_vol_rlim` 8.56.
→ 매핑이 틀리지 않았다는 증거로 쓸 것.

### 러너

```bash
set -a && . ./.env && set +a
/usr/bin/python3 scripts/kis_short_selling_backfill.py --limit 30   # 유동성 상위 30종목
/usr/bin/python3 scripts/kis_short_selling_backfill.py --limit 0    # 전체 유니버스(≈35분)
```
- DB 접속은 **127.0.0.1:5434**(host). `.env` 의 `POSTGRES_HOST=postgres` 는 컨테이너 내부 이름이라
  호스트에서 쓰면 안 된다 → 러너는 `PGHOST_HOST`/`PGPORT_HOST` 를 따로 본다.
- **`/usr/bin/python3` 를 쓸 것** — 세션 기본 `python3` 는 hermes venv 라 psycopg2 가 없다.
- 유동성 유니버스는 `market_data` 기반이고, 비면 `stocks` 마스터로 폴백한다(빈 DB 함정 회피).
- 진행파일 `data/kis/short_selling_progress.json` — 같은 구간 재실행은 전부 스킵된다.
  구간을 바꾸거나 `--ignore-progress` 를 써야 실제 재수집된다.
- KIS 호출 규율: 3.0초+지터, 실행당 상한(`--max-calls`, 기본 600),
  자격증명 오류(EGW00102/EGW00103)는 재시도 없이 즉시 종료.

### 선행 마이그레이션

`init-scripts/postgres/11_krx_short_selling_migration.sql` (적용 완료)
- `total_volume BIGINT` 추가 — **리더가 이 컬럼을 읽는다**. 그전에는 컬럼 부재로 예외 →
  `short_selling_ratio` 가 항상 0.0 이었다.
- `stock_name VARCHAR(100)` 추가(services/krx-collector 저장소 스키마와 정합).
- `uq_krx_short_selling_date_code` UNIQUE(trade_date, stock_code) — 업서트에 필요.
  (적용 시점 테이블이 0행이라 충돌 위험 없음.)
- `idx_krx_short_code_date (stock_code, trade_date DESC)` — 종목별 시계열 조회용.

⚠️ `02_swing_pipeline.sql` 의 원래 CREATE TABLE 은 손대지 않았다. 신규 DB 는
initdb 가 알파벳 순으로 `11_*.sql` 까지 실행하므로 동일한 최종 스키마가 된다.

## 2. 공매도 **잔고**(short interest)를 주는 소스는 없다 — 실측

`short_interest_ratio`(잔고/상장주식수)와 `days_to_cover`(잔고/일평균거래량)는
**공매도 잔고**를 요구한다. 다음을 모두 확인했고 전부 실패다.

### (a) KIS OpenAPI — 잔고 엔드포인트 없음

레포 클라이언트로 직접 프로브(`services/kis-collector/kis_app/client/kis_client.py`):

| 후보 path | tr_id | 결과 |
|---|---|---|
| `/uapi/domestic-stock/v1/quotations/daily-short-sale-balance` | FHPST04840000 | **404** |
| `/uapi/domestic-stock/v1/quotations/inquire-short-sale-balance` | FHPST04850000 | **404** |
| `/uapi/domestic-stock/v1/quotations/short-sale-balance-trend` | FHPST04860000 | **404** |
| `/uapi/domestic-stock/v1/quotations/short-sale` | FHPST04830000 | **404** |
| `/uapi/domestic-stock/v1/ranking/short-sale-balance` | FHPST04870000 | **404** |
| `/uapi/domestic-stock/v1/quotations/short-sale-balance` | FHPST04840000 | **404** |
| `/uapi/domestic-stock/v1/quotations/daily-loan-balance` | FHPST04820000 | **404** |

(대조군: `.../quotations/inquire-price` FHKST01010100 → 200 정상.
 `.../quotations/daily-credit-balance` FHPST04760000 → HTTP 200 +
 `OPSQ2001 ERROR INPUT FIELD NOT FOUND [FID_COND_SCR_DIV_CODE]` — 즉 **그 경로는 존재**하고
 파라미터만 틀린 것. 404 그룹과 확실히 구분된다.)

**결정적 근거**: KIS 공식 샘플 저장소 `koreainvestment/open-trading-api` 의 전체 트리(1,647 경로)에서
공매도 관련 API 는 **2개뿐**이다.
- `examples_llm/domestic_stock/daily_short_sale` → `daily-short-sale` FHPST04830000 (**체결**, 사용 중)
- `examples_llm/domestic_stock/short_sale` → `/uapi/domestic-stock/v1/ranking/short-sale`
  ([국내주식-133] 국내주식 공매도 **상위종목** — 순위분석. 잔고 아님)
→ KIS 에 공매도 잔고 API 가 **없으므로**, 개발자센터에 신청해서 풀 수 있는 문제가 아니다.

### (b) KRX OpenAPI — 공매도 서비스 자체가 없음

공식 서비스 목록(`https://openapi.krx.co.kr/contents/OPP/INFO/service/OPPINFO004.cmd`)의
**주식** 카테고리는 일별매매정보(유가/코스닥/코넥스)·신주인수권증권/증서·종목기본정보뿐이고
공매도 항목이 **없다**.

경로 실측(3.0초+지터, 3콜만 사용, 재시도 없음):

```
sto/sht_bydd_trd → HTTP 404 {"respMsg":"[svc/apis/sto/sht_bydd_trd] API referenced by the path does not exist.","respCode":"404"}
sto/srt_bydd_trd → HTTP 404 {"respMsg":"[svc/apis/sto/srt_bydd_trd] API referenced by the path does not exist.","respCode":"404"}
sto/stk_bydd_trd (대조군, data.krx.co.kr 호스트) → HTTP 404 HTML (이 호스트는 /svc/apis 미제공)
```

여기서 중요한 구분: **404 `API referenced by the path does not exist` 는 "키 미승인(401
`Unauthorized API Call`)" 과 다르다.** 경로 검증이 승인보다 먼저 일어나므로, 이 404 는
**승인 여부와 무관하게 그 서비스가 존재하지 않는다**는 뜻이다.
(대조군 data-dbg 호스트는 1콜에서 read timeout 이 났고 이후 콜은 JSON 을 정상 반환 —
호스트는 살아 있고 첫 콜이 일시적으로 느렸던 것.)

또한 `https://openapi.krx.co.kr/.../notice/OPPCOMM001_S2.cmd?bbsSeq=5`
("KRX Open API 미제공 데이터에 대한 안내", 2026-06-01) 페이지는 이 세션에서
**"서비스 제공 불가능 — 일시적 접근 불안정"** 만 반환했다(본문 확인 실패).

### (c) 공공데이터포털 — 공매도 데이터 없음

data.go.kr 의 금융위원회 주식 계열 오픈API 는 주식시세정보 / 주식발행정보 / 기업재무정보 등이고
**공매도 잔고 API 가 없다**.

### (d) DART — 공매도 데이터를 제공하지 않는다. (재무·공시 전용)

### 결론 — 남은 유일한 후보와 그 위험

공매도 잔고는 사실상 **KRX 정보데이터시스템(data.krx.co.kr) "공매도 종합정보"의
수동 CSV 다운로드**가 유일하다. 그런데:
- 이 계정/IP 는 과거 요청 제한 위반으로 차단 이력이 있고, 팀 정책상
  `comm/bldAttendant/getJsonData.cmd`(pykrx 가 쓰는 경로)는 **호출 금지**다.
  `services/krx-collector/.../short_selling_collector.py` 가 이 경로에 의존하기 때문에
  지금까지 `krx_short_selling` 이 0행이었다.
- CSV 다운로드(`comm/fileDn/*`)는 다른 서블릿이지만 **같은 호스트**이고, bld 코드를
  추측해야 하며, 실패 시 다른 작업자의 KRX 수집기까지 IP 차단 위험을 공유한다.
- 같은 페이지(openapi.krx.co.kr)가 이번 세션에서 "서비스 제공 불가능"을 반환했다.
→ **호출하지 않았다.** 이득(잔고 1개 피처) 대비 공유 IP 차단 위험이 과도하다고 판단.

## 3. `days_to_cover` 는 잔고 데이터가 있어도 0 이다 — 리더 SQL 버그 (실측)

`feature_pipeline.py`(#16)의 쿼리를 임시 테이블 + 트랜잭션 롤백으로 **원문 그대로** 실행:

```sql
SELECT si.short_interest, AVG(sp.volume) as avg_vol
FROM short_interest si JOIN stock_prices sp ON si.stock_code = sp.stock_code
WHERE si.stock_code='005930' AND sp.trade_date <= '...' AND sp.trade_date >= '...'
GROUP BY si.short_interest ORDER BY si.trade_date DESC LIMIT 1;
```

```
ERROR:  column "si.trade_date" must appear in the GROUP BY clause or be used in an aggregate function
```

`GROUP BY si.short_interest` 로 좁혀 놓고 `ORDER BY si.trade_date` 를 쓴다 → Postgres 가 거부 →
리더의 `except` 가 삼키고 0.0. **`market_breadth` 와 같은 부류의 "리더 코드 버그"** 다
(10_feature_revival_objects.sql 주석 참조). 같은 트랜잭션에서 `short_interest_ratio` 쿼리(#15)는
정상 동작함을 확인했다 — 즉 #15 는 데이터만 있으면 살아난다.

`stock_prices` 는 다른 작업자가 만든 뷰(`market_data` 별칭)가 이미 존재한다
(`init-scripts/postgres/10_feature_revival_objects.sql`). 없는 것은 `short_interest` 테이블뿐이고,
그 테이블을 채울 데이터가 없다.

## 4. 다른 작업자가 참고할 것

- **`krx_short_selling` 을 다시 0으로 만들지 말 것.** writer 를 추가한다면 업서트 키
  `(trade_date, stock_code)` 를 지키고, `total_volume` 을 반드시 함께 채워야 한다
  (비워 두면 `short_selling_ratio` 가 다시 0 이 된다).
- `services/krx-collector/.../short_selling_collector.py` 는 **pykrx 의존 + 수집기에서
  `stock_code` 를 넣지 않는 status 경로**가 있어 그대로 돌리면 `stock_code='NaN'` 플레이스홀더
  행을 만든다(`docs/close_screener_PLAN.md` 에 실측 기록). 이 러너(KIS)를 대체 경로로 쓰는 편이 낫다.
- 이 창(2026-05-26~)에는 **공매도 체결 0행이 20건** 섞여 있다(2,393행 중 2,373행만 `short_volume>0`).
  휴장/무공매도일 수 있으니 "0 = 수집 실패"로 오판하지 말 것.
- 검증용 날짜로 **2026-06-20 을 쓰면 안 된다 — 토요일(휴장)** 이다. `short_selling_ratio` 조회는
  `trade_date = %s` **정확 일치**이므로 휴장일은 구조적으로 0 이다. 2026-06-19 또는 2026-06-25 를 쓸 것.

## 5. 다음 후보 작업

1. **전 종목 백필**: `/usr/bin/python3 scripts/kis_short_selling_backfill.py --limit 0` (≈35분, 2,700콜).
   현재는 30종목만 있으므로 학습 패널의 대부분 종목은 아직 0 이다. **권장 1순위.**
2. **`short_interest_ratio` 살리기**: 공매도 잔고 확보가 선행되어야 한다.
   KRX CSV 수동 다운로드(위험 검토 필요) 또는 유료 데이터 벤더 → 확보되면
   `short_interest(stock_code, trade_date, short_interest, total_shares)` 테이블을 만들어
   리더를 고치지 않고 살릴 수 있다(다른 작업자가 `stock_prices` 뷰로 쓴 방식과 동일).
   `total_shares` 는 KIS `inquire-price` 의 `lstn_stcn` 으로 이미 확보 가능하다.
3. **`days_to_cover` SQL 패치**: 위 3절 버그. `GROUP BY` 를 `si.short_interest` 대신
   서브쿼리/`DISTINCT ON` 으로 바꾸는 1줄 수준 수정. `feature_pipeline.py` 는 팀 규약상
   "수정 금지 파일"로 취급되므로 반드시 합의 후 진행할 것.
