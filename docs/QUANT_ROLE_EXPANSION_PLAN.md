- 지금 analyist_dd 에는 **퀀트 4역할**(리서처·모델엔지니어·트레이더·리뷰보드)만 있다. gstack 의
  `office-hours`(YC 오피스아워·대화형), `plan-eng-review`(EM 모드 계획 락), `health`/`context-save`

  gstack 에 존재하지만 analyist_dd 역할로는 **배선돼 있지 않다**(레포 검색 0건).
- 그 결과 최근 6건의 사고가 **역할 부재와 정확히 일치**한다(§1). 넷은 "만들었는데 검증할 사람이 없다"였다.
- 설계 원칙 3개:
  1. **신규 5역할은 '감사·게이트' 역할이다 — 생산 코드를 소유하지 않는다.** 기존 역할의 파일 스코프와

     신규 역할은 **읽기 전용 감사 + 자기 산출물 디렉터리만 write**.
  2. **게이트는 산문이 아니라 실행 가능한 검사다.** 통과를 주장할 수 있으면 게이트가 아니다.
  3. **릴리즈는 챔피언 교체·피드 계약·크론 변경·이미지 교체를 포함**하고, 릴리스 후 검증과 롤백 명령이

## 3. 역할별 정의 (5개)

### 3.1 quant-office-hours — 전략 오피스아워
- **목적**: "이걸 만들 가치가 있나 / 이 게이트를 유지할까"를 **대표(사용자)와 함께** 판단한다.
  알고리즘 판단이 아니라 **자원 배분과 전략** 판단이다.
- **입력**: 지난 주 실측(원장·저널·피드·게이트 비용), 대표의 질문.
- **출력**: `docs/office_hours/<YYYY-MM-DD>.md` — 결정 1줄 + 근거 수치 + 되돌리는 조건 + `Supersedes:` 체인
  (gstack office-hours 의 revision chain 과 동일한 규약).
- **게이트(하드)**: ① 모든 주장에 실측 수치를 붙인다(수치 없는 주장은 '가설'로 표기) ② 결정마다
  **되돌리는 조건**을 쓴다 ③ 이 문서는 결정 기록이지 실행 권한이 아니다(실행은 §4 순서).
- **크론**: 없음(대화형). 원하면 금 16:00 리마인더 1건만.
- **오늘 잡았을 것**: close 경로 R1+HEAT 3세션 무진입(설계 방어 vs 문턱 재검토) — 지금은 이 판단이
  아무 역할에도 배정돼 있지 않아 대표가 물어볼 때마다 즉석에서 계산한다.

### 3.2 quant-em-lock — 계획 락 (EM 모드)
- **목적**: 실험·릴리스가 **사전 등록된 계약**을 갖고 시작하게 한다. 결과를 보고 기준을 만들지 못하게 한다.
- **입력**: 백로그 항목 / 릴리스 요청.
- **출력**: `docs/locks/<id>.lock.json` — {목표, 대조군, 성공 문턱, 폴드·시드, est_minutes, 컨테이너 timeout,
  표본 출처, **데이터 소스별 러너·스케줄 표**, 롤백}. 락 없는 항목은 착수 불가.
- **게이트(실행 가능한 검사)**: `scripts/audit_em_lock.py`
  ① `counterfactual`·`success`·`est_minutes`·`timeout` 4필드 존재 ② est_minutes 실측 근거(직전 런 cell/min)
  ③ 표본 유니버스 재현성(같은 함수 4회 교집합 100%) ④ 신규 데이터 의존이면 러너·스케줄 표 필수
  ⑤ 승격·릴리스 문턱은 **사전등록 값과 일치**해야 한다(오늘 0.0 vs 0.02 불일치가 이 검사로 잡힌다).
- **오늘 잡았을 것**: `--min-improvement 0.0` vs 사전등록 +0.02 불일치, DART 러너 부재.

### 3.3 quant-staff-engineer — 측정·인프라 정합성
- **목적**: "숫자가 어떻게 만들어졌나"와 "경로가 실제로 돌았나"를 본다. 성능 판정은 하지 않는다.
- **소유(신규)**: `reports/audit/**`, `scripts/audit_*.py`. **기존 역할 파일은 읽기만.**
- **게이트(실행 가능한 검사)**:
  ① 창 정합성: 다중창 결과에 OOS/인샘플 표시가 있는가, `windows_excluded` 확인, pooled−날짜별 gap 이상치
  ② 표본 재현성: 유니버스·시드 결정성(교집합 100%)
  ③ 리포트 오용: `per_exp` 에 실측(비-arm) 값을 싣지 않았는가(스코어보드 오독 방지)
  ④ 경로 정합성: 루프 기동 시각 vs 청산 창(09:00–09:10) · 브리지/저널/원장의 시각 일치
  ⑤ 인프라: 컨테이너 재생성 창(평일 20:00~20:12) 침범, 좀비·load·디스크, UTC/KST 혼재.
- **출력**: `reports/audit/staff_<날짜>.json` + 이상만 stdout.
- **오늘 잡았을 것**: 9/30 청산 창 미기동, 위생 좀비 4시간 방치.

### 3.4 quant-qa-lead — 검증 (prod 에서 터질 것)
- **목적**: "테스트는 통과하는데 운영에서 터지는" 유형을 릴리스 전에 잡는다. gstack `/qa` 의
  "fix + atomic commit + regression test" 를 퀀트판으로: **회귀 검사를 남긴다**.
- **소유(신규)**: `reports/qa/**`, `scripts/qa_*.py`. 기존 역할 파일은 읽기만.
- **게이트(실행 가능한 검사)** — 최소 4종:
  ① **라이브 스코어 분포**(MT116 재발 방지): 스크리너 산출물의 top20 max confidence 와 절대문턱 초과 건수,
     `batch_type`. 기준: `signal` 배치가 0건이면 **경보**(경로가 닫힌 것)
  ② **피드 계약**: 전략별 필수 필드·`signal_date`·`valid_until`·신선도·계약 위반 0
  ③ **주문 경로**: 페이퍼 검증 없는 실주문 변경 금지, 킬스위치 존재, 한도(일 3건·종목 10%·동시 3·총 30%)
  ④ **회계**: 저널↔브로커 대조, `fees` 반영(현재 0), 미청산 포지션 슬롯 점유
- **출력**: `reports/qa/qa_<날짜>.json` + 실패 항목별 재현 명령. **실패가 있으면 릴리스 보류**를 릴리즈엔지니어에 통보.
- **오늘 잡았을 것**: MT116(릴리스 15분 내), fees=0.

### 3.5 quant-release-engineer — 릴리스 (ship + land-and-deploy)
- **목적**: 챔피언 교체·피드 계약 변경·크론 변경·이미지 교체를 **한 세트의 절차**로 만든다.
  "approved → verified in production" 을 한 명령으로 닫는다.
- **소유(신규)**: `docs/releases/<YYYY-MM-DD>-<slug>.md`, `tools/release_*.sh`. 운영 파일 수정은 §4 순서의
  승인 단계를 거친다(헌장: 챔피언 승격·크론·계약은 사람/리뷰보드 승인).
- **절차(하드, 순서 고정)**:
  1. **동결**: 관련 산출물의 소비자 목록 확정(누가 읽는가)
  2. **백업**: 되돌릴 산출물의 **정확한 경로**를 릴리스 문서에 기록(오늘: `champion_prev_<ts>` 자동 생성 확인)
  3. **dry-run**: 게이트 CLI 의 dry-run/`would_*` 상태를 **문자열로 인용**(오늘 `would_promote`/`kept_incumbent`)
  4. **적용**
  5. **릴리스 후 검증(15분 내)**: QA리드 검사 재실행 → ① 배치타입 `signal` ② 피드 전략별 건수>0
     ③ 루프 `last_cycle` 갱신·브리지 connected. **검증 실패면 즉시 6번.**
  6. **롤백 명령 보유**: 릴리스 문서에 복원 명령 1줄(`champion_promote --candidate <backup>` 등)
- **출력**: 릴리스 문서(절차·dry-run 인용·검증 결과·롤백 명령) + `reports/qa/` 결과 링크.
- **오늘 잡았을 것**: MT116 — 릴리스 후 검증이 없어 "배치가 raw_fallback 으로 뒤집힌 것"을 9시간 뒤에 발견했다.

## 4. 실행 순서와 락 (기존 4역할과의 관계)

```
[대표+오피스아워] 결정 문서
      ↓ (결정 → 계획)
[EM 락] 실험·릴리스 등록 계약(문턱·표본·러너표)
      ↓ (락 통과분만)
[리서처] 데이터/피드  →  [모델엔지니어] 학습·검증  →  [트레이더] 주문·피드
      ↓ (각 단계 산출물)
[스태프엔지니어] 정합성 감사(측정·경로·인프라)
      ↓
[QA리드] 릴리스 전 필수 검사(스코어 분포·계약·주문경로·회계)
      ↓ (실패 0)
[릴리즈엔지니어] 동결→백업→dry-run→적용→15분 검증→(실패 시)롤백
      ↓
[오피스아워] 결과 회고 → 다음 결정
```

- **락 충돌 금지**: 신규 5역할은 생산 파일을 소유하지 않는다(§3 의 소유 경로만 write).
- **역할 틱 예산**: 기존 가드(장중 09:00–15:30 금지, load1 3.5, 직렬화)를 신규 역할에도 그대로 적용.
- **회고 채널**: 릴리스 결과·QA 실패는 다음 오피스아워 입력으로 되돌린다(순환 고리).

## 6. 리스크와 가드

1. **역할 중복·충돌** — 신규 역할이 생산 코드를 만지면 2026-09-25 형제 충돌이 재발한다. 소유 경로를
   §3 대로 고정하고, 쓰기 전 mtime 확인 + 스코프 락 규칙을 스킬에 명시한다.
2. **가짜 승인** — 게이트를 산문으로 두면 통과를 주장만 하게 된다. P1 을 먼저 하는 이유다.
3. **토큰·시간 예산** — 5역할을 매일 돌리면 순수 비용이다. 크론은 2개만(15:50 QA, 토 09:00 스태프),
   나머지는 이벤트 트리거로 둔다. 역할 틱에는 호출·토큰 상한을 코드로 강제한다.
4. **권한 경계** — 챔피언 승격·크론 파일 수정·피드 계약 변경은 **여전히 사람/리뷰보드 승인**이다.
   릴리즈엔지니어는 '준비·검증·롤백'을 소유하고 '승인'은 소유하지 않는다.
