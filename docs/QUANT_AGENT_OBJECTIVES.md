# 퀀트 3역할 — 궁극 목표와 정렬 원칙

**사용자 지시(2026-09-25)**: "퀀트리서처의 목표는 양질의 데이터가 잘 정제되어 모델에 학습되도록
하는 것, 퀀트모델엔지니어의 목표는 모델의 AUC 등 성능을 향상시키는 것, 퀀트트레이더의 목표는
트레이딩을 통해 돈을 더 많이 버는 것. 이 최종 목표를 위해 궁극적으로 일하도록 해야 해."

이 문서는 그 지시를 **측정 가능한 계약**으로 바꾼 것이다. 각 역할의 보고는 북극성 지표로 시작하고,
지표가 움직이지 않으면 조용히 공전하지 않고 사람에게 올린다.

## 목표 사슬

```
최종 목표: 순손익(₩) 극대화
   ▲
   │  신호 품질을 결정
트레이더      순손익(₩) · 건당 기대값(₩) · 승률 · 회전
   ▲
   │  피처·라벨을 공급
모델엔지니어  로버스트 AUC(확장창 워크포워드 다중폴드 평균)
   ▲
   │  학습 데이터를 공급
퀀트리서처    모델에 들어가는 데이터의 품질·커버리지 (DQ, 살아있는 피처)
```

**사슬 책임**: 리서처는 "많이 모았다"가 아니라 **모델이 쓸 수 있게 정제됐다**로 판정된다.
엔지니어는 "실험을 돌렸다"가 아니라 **로버스트 AUC가 움직였다**로 판정된다.
트레이더는 "주문을 냈다"가 아니라 **원(₩)이 늘었다**로 판정된다.

## 북극성 지표와 출처 (자기신고 금지)

| 역할 | 북극성 | 출처(산출물) | 판정 규칙 |
|---|---|---|---|
| 리서처 | 모델 학습 데이터의 품질·커버리지 | `data/reports/dq_snapshots/dq_*.json` (Prometheus 실측) | DQ breach 0 · 살아있는 피처 ≥ 죽은 피처 · 신선도 정상 |
| 엔지니어 | 로버스트 AUC | `data/reports/model_engineer_ledger.jsonl` (`per_exp.*.mean`) + 챔피언 `auc.txt` | 폴드 평균이 기준선 **+0.02 이상**이어야 신호(폴드 std ±0.03 감안) |
| 트레이더 | 실현 순손익(₩) | `trader-agent/journal/trade_journal.sqlite3` (청산 거래만) | 총액 증가 · 기대값 > 0 · 회전 유지 |

한 화면 요약: `python3 scripts/quant_scoreboard.py`
역할별 한 줄: `python3 scripts/quant_scoreboard.py --stanza trader|engineer|researcher`

## 운용 원칙

1. **돈은 %가 아니라 원으로 본다.** 실측(2026-09-25): 평균수익률 **+0.32%** 인데 실현 총액은
   **-7,839원**. 포지션이 큰 거래에서 더 크게 잃으면 수익률 평균은 착시가 된다.
   트레이더의 승격·폐기 판단은 총액과 기대값(원/건)으로만 한다.
2. **단일분할 AUC를 성공 판정에 쓰지 않는다.** 폴드 표준편차가 ±0.03 수준이라 단일 분할
   차이는 노이즈와 구분되지 않는다. 확장창 워크포워드 다중폴드 **평균**만 판정에 쓴다.
3. **한 번에 한 레버.** 실험은 단일 변수만 바꾸고 대조군을 명시한다(현재 레버 소진 상태:
   라벨 축 3종 종결, 남은 것은 유니버스·피처·데이터 축).
4. **무개선이 계속되면 사람에게 올린다.** 침묵하는 자율 루프는 가치가 없다.
   - 엔지니어: 기준선 대비 +0.02 미달이 **3사이클** 연속 → "새 레버 필요" 사람 승인 항목
   - 리서처: DQ breach 지속 또는 살아있는 피처 정체 → 승인 항목
   - 트레이더: 신규 진입 없음이 **3일** 이상 → 회전 정지 경고(자금이 묶여 돈을 못 벎)
5. **모든 보고는 3부로 끝난다**: ① 내가 할 일(자율) ② 사용자 승인 필요 ③ 🙋 사람이 직접
   해야 할 일(없으면 "없음"이라고 쓴다).

## 현재 상태 (사슬이 지목하는 병목)

- **💰 트레이더가 최종 목표의 병목이다**: 실현 -7,839원, 기대값 -253원/건, 승률 38.7%,
  그리고 **4일째 신규 진입 0건**(보유 10/10 상한 도달) → 경험이 쌓이지 않고 자금이 묶여 있다.
  상한 상향 또는 청산 규칙 조정이 필요하다(사람 결정 사항).
- **📈 엔지니어**: 로버스트 최고 **0.5406** 이 기준선 자체(라벨 축 3종에서 개선 없음).
  남은 레버는 유니버스(U1 진행 중)뿐 — U1이 결과를 내지 못하면 데이터 축으로 넘어가야 한다.
- **🔬 리서처**: DQ warn(종목상수 피처 38.2%)과 **죽은 피처 97 > 살아있는 76** —
  모델에 들어갈 신호의 절반 이상이 죽어 있다. 이는 엔지니어의 상한을 직접 제한한다.

## 자동화

- 스코어보드 갱신: `scripts/quant_scoreboard.py` (JSON + `docs/QUANT_SCOREBOARD.md`)
- 각 구동기 틱이 자기 북극성 한 줄을 출력에 포함한다
  (`researcher_cycle.py` → 리서처 스탠자, `model_engineer_cycle.py` → 엔지니어 스탠자)
- 사람 개입 필요 항목은 스코어보드가 `needs_human` 으로 모아 리포트에 그대로 실린다.
