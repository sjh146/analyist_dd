# 챔피언 승격 기록 (2026-09-25) — 결정 1: 승격 기준선 하향

## 결정
사용자 승인(결정 1): **승격 기준선을 실측 로버스트 수준(0.53)으로 하향**해, 최근 데이터로
학습한 챌린저가 승격될 수 있게 한다.

## 왜 0.55 가 잠금이었나 (실측 근거)
- 챔피언 `auc.txt` = 0.613053(단일 분할, 2026-08-14 학습) → `robust_auc.json` 부재 →
  기준선 = `min(0.6131, 0.55)` = **0.55**
- 같은 챔피언의 5폴드 견고성 실측: 0.4962 / 0.5228 / 0.5446 / 0.5281 → **평균 ≈ 0.523**
- as-of 누수 제거 후 4구성 실측: 0.5326 ~ 0.5400 (`docs/asof_measurement_20260925.md`)
- ⇒ **실질 상한 ≈ 0.54 < 0.55** → 어떤 정직한 후보도 통과 불가, 챔피언이 8/14 이후 동결

## 변경한 것
1. `services/xgboost-ml/app/training/champion_promote.py`
   - `min_auc` / `legacy_baseline_cap` 기본값 **0.55 → 0.53** (근거 주석 포함)
   - **지표 동형성 가드** 추가: 기준선이 `auc_mean`(다중 시드)인데 후보가 단일 분할만 있으면
     비교 불가로 거부. 단, 기준선 metric 이 `ensemble_auc` 면 단일 분할끼리 비교이므로 통과
     (무조건 막으면 생산 경로가 영영 승격 못 하는 새 잠금이 생긴다 — 실제로 이 함정을 밟을 뻔했다).
2. `scripts/full_pipeline_dd.sh` — 파이프라인이 명시적으로 넘기던
   `--min-auc 0.55 --legacy-baseline-cap 0.55` 를 **0.53** 으로. (기본값만 바꾸면 무효였다)
3. `scripts/champion_robust_eval.py` — `--write` 대상이 승격 기준선 파일을 **덮어쓰지 않도록**
   `robust_walkforward.json` 으로 분리. 워크포워드 프로토콜과 생산(단일 분할) 지표를 섞으면
   비교가 느슨해진다(워크포워드 값이 보통 더 낮아 단일 분할 후보가 쉽게 통과).

## 의미와 한계 (정직한 평가)
- **얻은 것**: train/serve skew 축소 — 학습 데이터가 8/14 → **9/23** 까지로 갱신(약 40일 → 5일).
  월요일 매매가 최근 시장을 본 모델로 이뤄진다.
- **한계**: 후보의 0.5513 은 **단일 분할** 값이라 챔피언의 0.6131(역시 단일 분할)과 직접
  비교할 수 없다. 두 모델의 정직한 로버스트 수준은 0.52~0.54 구간이며 서로 통계적으로
  구분되지 않는다. 따라서 이번 승격은 "**더 나은 모델**"이 아니라 "**더 최근 모델**"로
  정당화된다(모의투자 계좌이므로 위험은 낮다).
- **남은 과제**: 생산 학습 경로(`retrain_champion`)가 `auc_mean`(다중 시드) 을 내지 않아
  지표 동형 비교가 불가능하다. 다음 개선은 이 경로에 다중 시드 지표를 추가하는 것.
